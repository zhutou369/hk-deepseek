上個禮拜幫一間做網購嘅中小企睇佢哋嘅客服自動回覆流程，發現佢哋用 DeepSeek 生成產品描述時，格式一時大一時細，有時仲會無端端加咗一大段廢話。我打開佢哋個系統提示詞一看，原來只寫咗一句「請用繁體中文回覆，格式要靚」。難怪。

我測試時發現，DeepSeek 嘅系統提示詞（System Prompt）其實好影響輸出穩定度，尤其係當你要求固定格式（例如 JSON、表格、固定欄位）嘅時候。以下係我喺 2024 年 12 月尾用網頁版同 API 實測嘅心得，唔使寫程式都跟得到。

## 第一步：用「角色＋任務＋格式」三層結構寫提示詞

好多人寫系統提示詞，會直接寫「你係一個助手，幫我生成產品描述」。咁樣太模糊，模型唔知你嘅格式底線喺邊。

我實測有效嘅寫法係分三層：

1. **角色**：明確講「你係一個香港網店文案專員，負責寫 50 字內嘅產品短描述」。
2. **任務**：講清楚輸入係咩、輸出要包含邊幾個欄位。例如「輸入會有一個產品名同三個賣點，你要輸出一個 JSON 物件，包含 title、desc、price_tip 三個 key」。
3. **格式**：直接指定「只輸出 JSON，唔好有任何解釋文字，唔好用 markdown code block」。

呢個三步結構，我試過用喺 API 同網頁版，輸出格式嘅一致度明顯高過求其寫一句。如果你未熟悉基本提示詞概念，可以睇吓站內嘅 [DeepSeek 提示詞入門教學](/posts/deepseek-prompt-basics/)，入面有講點樣分開 system 同 user 訊息。

## 第二步：加入明確嘅輸出範例（Few-shot）

第二個關鍵係畀範例。我上週升級咗個測試腳本，發現如果只係用文字描述格式，模型有時會「自由發揮」；但係一旦喺系統提示詞入面加一個完整嘅輸入輸出例子，跟格式嘅比率就高好多。

例如你可以咁寫：

> 輸入：產品名「無線滑鼠」；賣點「靜音、輕巧、USB-C 充電」
> 輸出：{"title":"無線滑鼠","desc":"靜音輕巧，USB-C 快充，香港現貨。","price_tip":"建議零售價 $199"}

記住，範例要同你真實資料嘅結構一致，唔好求其作一個。另外，如果你用 API，可以將呢個範例放喺 system message 入面；如果係網頁版，就直接貼喺對話開頭。

順帶一提，如果你會用 API 大量生成，記得留意 [DeepSeek API 密鑰同用量限制](/posts/deepseek-api-key-and-limits/) 嘅說明，免得爆 quota 影響流程。

## 第三步：設定禁止事項同埋長度上限

第三步係講清楚「唔准做咩」。我測試時發現，模型好容易會加一啲客套話或者解釋，例如「好的，以下係您要嘅內容」。呢啲文字會令你之後用程式解析嗰陣好麻煩。

所以系統提示詞要加幾句：

- 「只輸出目標格式，唔好加任何開場白、結尾語或解釋。」
- 「如果輸入資料不足，輸出 {"error":"missing_data"}，唔好自己作。」
- 「每個欄位嘅字數上限：title 20 字、desc 50 字。」

呢啲禁止事項同長度限制，對固定格式嘅穩定性好有幫助。我實測喺 2024 年 12 月版本，加咗呢三句之後，格式錯誤率由大概三成降到一成左右（當然，唔同輸入複雜度會有差異，以官方文檔為準）。

## 常見問題

**問：系統提示詞越長越好嗎？**

唔係。太長會令模型分心，重點係結構清晰同範例準確。一般 200 至 500 字內已經好夠。

**問：網頁版同 API 嘅系統提示詞設定有冇分別？**

有。網頁版你要喺對話開頭自己打「系統指示：」；API 就有獨立嘅 system role。如果你用 API 遇到報錯，可以參考 [DeepSeek API 重試機制指南](/posts/deepseek-api-retry-guide/)。

**問：如果模型仍然唔跟格式，可以點做？**

先檢查範例係咪同真實輸入一致，再收窄任務範圍。有時將任務拆細（例如先生成大綱，再生成內容）會更穩。

**問：用本地模型跑 DeepSeek 有冇幫助？**

如果你追求完全可控同離線，可以試吓用 Ollama 跑蒸餾版，設定方法睇 [DeepSeek Ollama 本地部署教學](/posts/deepseek-ollama-local-setup/)。不過本地模型嘅格式跟從能力同官方 API 版本可能會有少少差別，要自己試。

**問：系統提示詞入面可以寫「以官方文檔為準」嗎？**

可以，但唔好靠佢嚟控制格式。最好都係寫明具體規則，唔確定嘅細節先叫模型參考官方資訊。

總括嚟講，想 DeepSeek 輸出格式穩定，記住三件事：三層結構、真實範例、明確禁止。你都可以去 platform.deepseek.com 睇吓最新 API 文檔，確認有冇更新嘅參數。
