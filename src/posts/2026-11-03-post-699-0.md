## 第一步：確認是否真的被風控

我測試時發現，DeepSeek 的登入錯誤提示其實有幾種。如果是密碼錯誤，畫面會顯示「帳號或密碼不正確」；如果是網絡問題，通常會卡在載入圈圈。但我這次看到的「帳號異常」字樣，根據幫助中心說明，通常與短時間內多次登入失敗、異地登入或系統偵測到異常行為有關。

建議你先做兩件事：

1. 換一個瀏覽器或用手機 App 登入，排除快取或 Cookie 問題。
2. 檢查綁定的電郵或手機是否收到安全通知。

如果兩者都正常，但依然被擋，那很大機會是觸發了風控。我之前寫過一篇[DeepSeek 網頁版登入排錯](/posts/deepseek-web-login-troubleshoot/)，裡面有更詳細的排查清單，可以先看那篇確認網絡環境。

## 第二步：提交申訴的具體做法

確認是帳號層面的問題後，我直接去 DeepSeek 官網的「聯絡我們」頁面填表。這裡要提醒：**不要重複提交**，我當時心急連續送了三次，結果收到系統回覆說「已收到您的請求，請勿重複提交」，反而拖慢了處理速度。

具體步驟如下：

1. 前往 platform.deepseek.com 登入頁，點擊右下角的「幫助」或直接搜尋「申訴」。
2. 填寫表單時，在「問題描述」欄位清楚寫明：帳號電郵、最後成功登入的時間、出現錯誤的畫面截圖（我附上了那張紅色提示圖）。
3. 提交後會收到一封自動回覆郵件，記下郵件裡的案件編號，之後跟進時報上編號會快很多。

另外，如果你有使用 API，也檢查一下 [API Key 與用量限制](/posts/deepseek-api-key-and-limits/) 頁面，看看是否有異常調用紀錄，這有助於向客服說明你的使用情況。

## 第三步：跟進與解封結果

提交申訴後，我當晚收到一封確認郵件，說「您的請求已進入審核隊列，預計 1-3 個工作天內回覆」。第二天下午，我再次嘗試登入，發現已經可以正常進入，但帳號設定裡多了一個「安全驗證」的提示，要求我重新綁定手機。

整個過程大約 36 小時。我測試時發現，如果你的帳號有綁定信用卡或正在使用 API 自動化工作流，審核時間可能會稍長，因為需要人工核對交易紀錄。建議在申訴信裡主動說明用途，例如「主要用於本地模型測試與自動化工作流」，這樣可以減少來回問答。

解封後，我立刻去改了密碼，並開啟了兩步驗證。如果你也在用 Ollama 跑本地模型，可以參考這篇[本地部署設定](/posts/deepseek-ollama-local-setup/)，裡面有提到如何避免頻繁切換網絡導致風控誤判。

## 常見問題

**Q1：申訴後多久會回覆？**
A：我實測是 36 小時左右，但官方說法是 1-3 個工作天，實際時間以官方回覆為準。

**Q2：沒有收到驗證碼怎麼辦？**
A：先檢查垃圾郵件箱，並確認手機號碼是否正確。如果超過 10 分鐘沒收到，可以換一個電郵地址重新註冊一個新帳號來聯絡客服，但不要用新帳號重複提交同一問題。

**Q3：帳號被鎖期間，API 還能用嗎？**
A：通常網頁版和 API 是連動的，我當時 API 也無法調用。建議先處理好帳號狀態，再繼續開發。

**Q4：申訴需要提供身份證嗎？**
A：一般不需要，除非涉及付費爭議。我這次只提供了電郵和截圖就解封了。

**Q5：如何避免再次被鎖？**
A：固定常用 IP、不要短時間內切換多個裝置登入、定期更新密碼。如果你會用[提示詞技巧](/posts/deepseek-prompt-basics/)大量生成內容，建議控制頻率，避免觸發自動化偵測。

最後提醒，以上流程基於我 2025 年 3 月的實際經驗，DeepSeek 的風控規則可能隨時調整，具體細節請以官方文檔為準。
