## 點解要分 R1 同 V3？

上週 upgrade 咗部本地機之後，我特登用同一個 prompt 分別餵畀 DeepSeek R1 同 V3（API 版本號以 2025 年 1 月公開嘅 deepseek-reasoner 同 deepseek-chat 為準），發現兩者唔止「一個會思考、一個唔會」咁簡單。R1 開思考模式時，輸出前面會多一段 `reasoning_content`，呢段唔計入最終答案，但會直接拖慢首次 token 嘅時間。V3 就冇呢個欄位，回應乾脆好多。

![DeepSeek R1 與 V3 架構對比示意](/static/images/photo-1607604276583-eef5d076aa5f.jpg)

如果你只係要查天氣、改文法、寫封email，R1 嘅思考鏈反而係負擔。相反，涉及多步推理、数学題、debug 邏輯，R1 嘅準確度會明顯高一截。呢個取捨就係本文想講清楚嘅核心。

## 我嘅實測設定同數據

我測試時用咗三條 prompt：一條簡單事實題（「香港飛東京幾多小時」）、一條中階推理（「幫我睇呢段 Python 點解會 index error」）、一條多步數學題。每條跑 5 次取中位數，溫度設 0.6，其餘用預設。

結果好直觀：簡單題 V3 平均 1.2 秒出第一個 token，R1 開思考要 3.8 秒；推理題 V3 雖然快，但答錯率約四成，R1 就穩定啱。換句話說，R1 唔係「慢」，而係「用時間換準確度」。如果你嘅工作流係批量處理，例如用 [Ollama 本地跑模型](/posts/deepseek-ollama-local-setup/) 做離線摘要，就要諗清楚呢個延遲接唔接受到。

## 三步教你按場景切換模型

**第一步：確認你嘅呼叫方式。** 如果你用 API，R1 對應 `deepseek-reasoner`，V3 對應 `deepseek-chat`，兩者 base URL 相同，但 R1 唔支援 temperature 等部分參數，呢點要以官方文檔為準。

**第二步：寫一個簡單路由。** 我喺自己嘅自動化工作流入面加咗個判斷：如果 prompt 包含「點解」「證明」「debug」呢類字眼，就丟去 R1；否則默認 V3。呢個做法唔使改太多代碼，慳返唔少時間。

**第三步：設定超時與重試。** R1 思考時間浮動較大，我建議將 timeout 設到 60 秒以上，並且參考 [API 重試教學](/posts/deepseek-api-retry-guide/) 加一層 backoff，避免長思考被誤判為失敗。

## 思考模式幾時開？三個判斷準則

第一，**答案有唯一正確解**嘅時候開，例如計數、邏輯判斷、法規查詢。第二，**你唔急**嘅時候開，例如離線報告、批量清洗數據。第三，**你需要解釋過程**嘅時候開，因為 R1 嘅思考鏈可以直接覆核。

反過來，以下情況我多數關思考：閒聊、翻譯、格式轉換、生成標題。呢類任務 V3 已經夠做，仲快幾倍。如果你想再壓縮成本，可以配 [Prompt 基礎技巧](/posts/deepseek-prompt-basics/) 把指令寫得更精準，減少來回。

## 常見問題

**問：R1 同 V3 價錢差幾多？**
答：以官方公開定價為準，R1 嘅輸出 token 單價通常高過 V3，而且思考鏈會消耗額外 token，實際成本要按你嘅用量計。

**問：可唔可以同一個對話入面切換？**
答：API 層面每次請求獨立指定模型，冇狀態繼承；網頁版就視乎介面有冇提供切換選項，以官方公告為準。

**問：本地用 Ollama 跑得到 R1 嗎？**
答：Ollama 有提供相應模型標籤，但硬件要求比 V3 高，顯示卡 VRAM 要預鬆啲，詳細規格睇官方模型頁。

**問：思考模式開咗但答案好慢，點算？**
答：先睇係咪 prompt 太模糊導致思考鏈過長，試下把問題拆細；另外檢查網絡同 timeout 設定。

**問：R1 會唔會答錯簡單題？**
答：會，而且有時因為過度思考而繞遠路，所以簡單任務我唔建議開。

如果你想由頭設定 API key 同了解用量限制，可以睇 [API Key 與限額說明](/posts/deepseek-api-key-and-limits/)，入門會順好多。總括嚟講，R1 同 V3 唔係邊個取代邊個，而係兩把唔同嘅刀，按場景揀就對了。
