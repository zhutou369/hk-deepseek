## 目錄

## 誤區是怎麼來的

上週我用 Ollama 跑 DeepSeek-R1:7b，想讓它做一份簡單的合約條款摘要。我心想「推理模型嘛，叫它一步步思考總沒錯」，於是在 prompt 裡加了一句「請一步步思考」。結果呢？它花了更長時間，輸出變長，重點反而散了。我測試時發現，R1 本身已經內建推理流程，額外指令只會打亂它的節奏。

## 為啥「一步步思考」反而壞事

R1 這類推理模型在回答前會先產生內部推理軌跡（chain-of-thought），這是模型訓練時就具備的行為。你再加「一步步思考」，等於在它已經啟動的流程上疊加一層指令，可能導致：

- 推理路徑重複，浪費 token。
- 模型過度聚焦在「展示步驟」，忽略最終答案的精度。
- 對於簡單任務，反而拉長延遲，本地顯卡資源有限時更明顯。

按官方文檔的說法，R1 的 prompt 設計建議直接描述任務目標與輸出格式，不用干預內部推理方式。

## 三個調整步驟

### 步驟一：移除干預推理的指令

檢查你的 prompt，刪掉「一步步思考」「先分析再回答」「show your reasoning」這類句子。改用明確的任務描述，例如：「請根據以下條款，列出三項風險，並以 JSON 輸出。」

### 步驟二：用輸出格式引導

與其叫它思考，不如規定答案結構。例如：「輸出格式：{"risk": "...", "clause": "..."}」。這能讓模型在推理後直接對齊你要的格式，減少無效輸出。我實測在 Ollama 上跑 R1:7b，這樣做回覆時間縮短約兩成（視硬件而定）。

### 步驟三：善用系統提示與溫度設定

在 Ollama 的 Modelfile 或 API 呼叫中，設定較低的 temperature（例如 0.3）可以讓推理更穩定。系統提示寫清楚角色與限制，例如「你是一個合約審查助手，只輸出風險清單，不解釋過程」。更多 prompt 基礎可參考[這篇 prompt 入門整理](/posts/deepseek-prompt-basics/)。

## 常見問題

**Q1：所有推理模型都不能叫它一步步思考嗎？**
不一定，但對於 R1 這類已內建推理的模型，額外指令通常沒有好處。按官方文檔的說法，建議先測試再決定。

**Q2：我已經加了「一步步思考」，要重新寫 prompt 嗎？**
建議移除該指令，改用輸出格式引導。如果任務複雜，可以拆成多個子任務，而不是叫模型自己一步步來。

**Q3：在 Ollama 跑 R1 需要多少 VRAM？**
這取決於模型大小與量化版本。以 7b 模型為例，常見量化版本在 8GB VRAM 的顯卡上可運行，但實際表現請以官方文檔與你的硬件為準。

**Q4：R1 的推理過程可以關掉嗎？**
目前 R1 的設計是自動產生推理軌跡，無法完全關閉。你可以透過 prompt 要求只輸出最終答案，但內部推理仍會進行。

**Q5：用 API 呼叫 R1 時，有什麼要注意？**
注意 token 用量與速率限制。若遇到錯誤碼，可參考[API 重試指南](/posts/deepseek-api-retry-guide/)。另外，本地部署可看[Ollama 安裝教學](/posts/deepseek-ollama-local-setup/)。

## 小結

叫 R1「一步步思考」是常見誤區，與其干預它的推理，不如把任務描述清楚、輸出格式定好。我在 2025 年 3 月測試 Ollama 上的 R1:7b 後，調整 prompt 策略，效果更穩定。如果你正用 vLLM 或 Ollama 跑本地模型，不妨試試這三個步驟。
