上週升級 DeepSeek 網頁版（2025 年 2 月版本）後，我特意翻了一遍設定頁。發現一個容易忽略的細節：**對話紀錄預設會用於「改善服務」**，也就是可能被抽樣去訓練模型。如果你在對話中貼過客戶報價、內部會議紀錄，這件事值得花三分鐘處理。

先講結論：DeepSeek 沒有提供「一鍵刪除所有歷史對話」的按鈕，但可以逐條刪除，也可以在設定中關閉「數據用於模型改進」。以下是我實際操作的步驟，以官方公開資訊為準。

## 我實測發現：對話預設會用來改進模型

我登入 chat.deepseek.com 後，點右上角頭像進入「設定」，再開「數據控制」分頁。當時「允許使用我的對話數據來改進模型」是開啟狀態，旁邊有一行小字說明「包括已刪除的對話」。換句話說，就算你之後刪除紀錄，之前已提交的內容仍可能留在訓練資料中。

這不代表 DeepSeek 會把你的對話公開，但對於處理敏感資料的用戶（例如香港中小企的財務或人事對話），最好主動關閉。我測試時發現，關閉後介面會顯示「已關閉」，但不會影響現有對話的顯示與搜尋。

## 關閉數據訓練的 3 個步驟

**步驟一：登入並進入設定**
用瀏覽器打開 chat.deepseek.com，登入後點擊右上角頭像，選擇「設定」。如果你主要用手機 App，路徑類似：右下角「我的」→「設定」。

**步驟二：找到「數據控制」分頁**
在設定選單中點「數據控制」（部分版本叫「私隱設定」）。這裡會列出兩個開關：一個是「允許使用對話數據改進模型」，另一個是「允許使用位置資訊」。把第一個關閉。

**步驟三：逐條刪除敏感對話（可選但建議）**
回到對話列表，長按或右鍵點擊單條對話，選擇「刪除」。注意：關閉訓練開關後，新對話不會再用於訓練，但舊對話若已進入訓練流程，刪除只影響你的帳戶顯示。想徹底避免，建議在關閉開關後，手動刪除含敏感內容的舊對話。

如果你需要保留紀錄但不想被訓練，可以考慮用 API 方式接入，並在請求中設定 `stream: false` 及不開啟歷史記憶。具體參數以官方文檔為準。另外，若你打算在本地跑模型，可以參考這篇 [Ollama 本地部署教學](/posts/deepseek-ollama-local-setup/)，完全離線就沒有這個煩惱。

## 常見問題

**Q1：關閉開關後，之前的對話還會被用於訓練嗎？**
官方沒有明確承諾「立即停止使用已提交的數據」。以我的理解，關閉只對之後的對話生效。建議把敏感舊對話刪除，並在關閉後重新開啟新對話。

**Q2：刪除對話後，伺服器上還有備份嗎？**
根據 DeepSeek 私隱政策，刪除後會在一定時間內從備份中移除，但具體時限未公開。如果你處理的是客戶個人資料，建議直接避免在對話中貼上身份證號碼或信用卡號。

**Q3：用 API 也會被訓練嗎？**
API 與網頁版的數據政策不同。一般來說，API 請求預設不用於訓練，但開發者應查閱 [API Key 與用量限制](/posts/deepseek-api-key-and-limits/) 頁面的最新說明。我實測時發現 API 回應速度穩定，但沒有找到明確的訓練開關，以官方文檔為準。

**Q4：關閉後會影響回答質素嗎？**
不會。模型本身已經訓練好，關閉開關只是不把你的新對話加入未來訓練，不影響當前推理。如果你覺得回答太長或太短，可以試試 [提示詞基礎優化](/posts/deepseek-prompt-basics/)，效果更直接。

**Q5：香港中小企應該怎麼做？**
最穩妥是私有化部署，例如用 Ollama 跑本地模型，數據不出公司網絡。如果必須用雲端版，至少關閉訓練開關、刪除敏感對話，並在內部指引中列明「不要在對話中貼上客戶全名與合約金額」。

## 香港中小企的折衷做法

我上週跟一間做貿易的中小企聊過，他們用 DeepSeek 寫電郵回覆，但會先把客戶名稱換成「A 公司」。這種做法雖然土炮，但有效。另一個做法是開一個專用帳戶，只用來做不敏感的文案工作，敏感查詢則用本地模型。

如果你遇到登入問題，可以參考 [網頁版登入排錯](/posts/deepseek-web-login-troubleshoot/)。記住，私隱設定不是一次性的，每次大版本更新後最好重新檢查一次。
