## 我實測的版本與基本認知

上週我把 DeepSeek 網頁版更新到 2025 年 3 月的介面版本，試了十幾份不同格式的檔案。老實說，它不是萬能文件閱讀器，而是一個「先抽取文字、再交給模型理解」的工具。這個認知很重要：如果檔案本身是掃描圖片或者排版混亂，解析結果就會打折扣。

![DeepSeek 檔案上傳介面操作示範](/static/images/photo-1513530534585-c7b1394c6d51.jpg)

我測試時發現，網頁版同一時間只能處理有限數量的檔案，而且每個檔案都有大小上限。具體數字以官方文檔為準，但一般來說，文字類檔案（PDF、DOCX、TXT）在幾 MB 以內都順利。如果你經常要處理大檔案，可以考慮用 API 分批上傳，或者參考 [DeepSeek API 密鑰與用量限制說明](/posts/deepseek-api-key-and-limits/) 裡面的分段策略。

## 支援格式與大小限制

根據我實際測試和官方公開資訊，常見支援格式包括：

- **PDF**：文字型 PDF 解析效果最好；掃描版 PDF 需要先做 OCR。
- **DOCX / DOC**：Word 文件基本沒問題，但複雜表格可能走位。
- **TXT / Markdown**：最穩定，適合放 prompt 或者知識庫片段。
- **CSV / XLSX**：可以讀取，但建議先清理合併儲存格。
- **圖片（JPG/PNG）**：主要用來做 OCR 文字提取，不是用來理解圖像內容。

大小方面，網頁版單檔通常有上限（我試過 10MB 以內的 PDF 都 OK），但一次過上傳太多檔案會拖慢解析。如果你要處理大量文件，可以參考 [DeepSeek 提示詞基礎寫法](/posts/deepseek-prompt-basics/) 裡面的「分段餵食」技巧，將大檔案切開幾份再上傳。

## 三步上傳與解析操作

以下是我日常用的步驟，不用記太多東西：

1. **準備檔案**：先將 PDF 裡面的掃描頁轉做文字（用任何 OCR 工具），確保文字可以選取。檔案名用英文和數字，避免特殊符號。
2. **上傳並等待解析**：在對話框按上傳按鈕，選檔案。上傳後不要馬上發問，等系統顯示「解析完成」先。如果看到錯誤碼，可以對照 [DeepSeek API 重試指南](/posts/deepseek-api-retry-guide/) 裡面的常見報錯處理。
3. **用指令引導提取**：不要只問「這份文件講什麼」，而是具體一點，例如「請列出第三頁的所有表格數據」或者「總結第二段的重點，用香港繁體中文」。

## 提升解析準確度的技巧

我習慣在上傳前做兩件事：第一，用免費工具將 PDF 壓縮到 5MB 以內；第二，如果文件有大量表格，我會先將表格轉做 CSV 再上傳，因為模型對純文字表格的理解準確度高一些。

另外，如果你是中小心企業想將檔案上傳功能接入自己的系統，可以看 [DeepSeek Ollama 本地部署教學](/posts/deepseek-ollama-local-setup/)，在本地環境處理敏感文件會更安心。不過要留意，本地模型的解析能力和網頁版未必完全一樣，以官方文檔為準。

## 常見問題

**問：上傳檔案後，模型說「無法讀取內容」怎麼辦？**
答：很大機會是掃描版 PDF 或者圖片解析失敗。建議先將檔案轉做文字型 PDF 或者 TXT 再試。

**問：一次可以上傳多少個檔案？**
答：網頁版有數量限制，我試過一次上傳 5 個檔案都正常，但具體上限以官方介面顯示為準。

**問：上傳的檔案會不會用來訓練模型？**
答：根據官方公開說明，用戶上傳的檔案主要用於當前對話解析，不會直接用來訓練。詳細數據處理政策請以官方文檔為準。

**問：Excel 裡面的公式會不會被解析？**
答：模型通常只讀取儲存格的顯示值，不會計算公式。建議先將公式轉為值再上傳。

**問：香港網絡上傳經常失敗，有沒有方法改善？**
答：可以試試切換網絡或者用有線連接。如果是 API 調用失敗，可以參考 [DeepSeek 網頁登入疑難排解](/posts/deepseek-web-login-troubleshoot/) 裡面的網絡檢查步驟。

最後提一句：檔案上傳功能很方便，但不要當它是萬能。複雜排版的文件，自己先清理一下，解析效果會好很多。
