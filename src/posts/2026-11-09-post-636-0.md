## 点解要睇隐私清单？

上周我帮一间观塘贸易公司设 DeepSeek API，他们想用来自动覆客户电邮。我测试时发现，如果直接将客户名、报价单号、银行户口贴入 prompt，资料会经网络送到 DeepSeek 服务器。根据 DeepSeek 2025 年 2 月公开的 API 文档，他们预设会保留输入数据最多 30 日作滥用检测，而且不建议传送个人敏感资料。

香港中小企没大企业的合规团队，但客户合约、员工身份证、供应商底价这类数据，一旦外泄就手尾长。所以这份清单不讲理论，只讲我实际做过的五步操作，等你可以安心用 DeepSeek 提升效率。

## 第一步：分清「可上云」与「不可上云」数据

我用最土方法：开一个 Excel 表，将公司数据分三类。

- 绿区：公开产品资料、通用客服 FAQ、不含个人身份的行内知识。这类可以直接喂给 DeepSeek。
- 黄区：客户公司名、联络人职位（不含电话身份证）、内部流程文件。要先去识别化，例如将「陈大文」改成「客户A」。
- 红区：身份证号码、银行账户、病历、未公开报价、员工薪酬。绝对不要输入 DeepSeek 网页版或 API。

我测试时试过将一份含客户地址的发票文字丢入 DeepSeek 网页版，结果它好准确地抽出地址，但同时代表资料已离开你部电脑。所以红区数据必须留在本地。

## 第二步：API 传输与储存加密设定

如果你用 [DeepSeek API 整合](/posts/deepseek-api-key-and-limits/)，有几个设定一定要做。

1. 强制 HTTPS：所有请求必须用 `https://api.deepseek.com`，不要贪方便用 HTTP。
2. 关闭日志记录：在你的应用程序码里面，确保不会将 request body 写入本地 log。我见过有公司将 prompt 连客户资料写入 debug log，结果备份上云。
3. 设定数据保留期限：根据文档，API 平台可以在账户设定调整数据保留选项；如果你的合约要求零保留，就要考虑本地模型。
4. 用环境变量存 API key，不要 hardcode 在前端。

上周升级后我发现，DeepSeek API 的错误码 `429` 代表请求过多，但不要把错误信息连 prompt 一起 log 低，因为 prompt 可能含敏感资料。可以参考 [API 重试机制指南](/posts/deepseek-api-retry-guide/) 来避免重复传送敏感内容。

## 第三步：本地 Ollama 方案作敏感数据缓冲

对于红区数据，我建议用 Ollama 跑本地模型做第一层处理。这个方法不会将数据送出街，适合香港中小企的网络环境。

具体操作：

1. 在公司一部有显卡的电脑安装 Ollama（官网 ollama.com 有 macOS 同 Windows 版本）。
2. 拉一个轻量模型，例如 `ollama pull deepseek-r1:7b`（以官方文档为准，模型大小约 4-5GB）。
3. 写一个简单 Python 脚本，先将敏感文件交给本地模型做摘要或实体识别，再将去识别化后的文字传去 DeepSeek API 做复杂分析。

我实测在一部 RTX 3060 的电脑跑 7B 模型，处理一页 A4 文字大约 20 秒，足够应付日常报价单去识别化。详细设定可以看 [Ollama 本地部署教学](/posts/deepseek-ollama-local-setup/)。

## 常见问题

**问：DeepSeek 网页版同 API 的数据保留政策有没有不同？**

答：根据 DeepSeek 公开信息，两者都预设可能保留数据作服务改进，但具体天数同选项以文档为准。如果你用 API，建议在账户设定检查有没有「关闭数据用于训练」的选项。

**问：我不想写程序，是不是只可以用网页版？**

答：网页版方便，但风险较高。你可以先用网页版处理绿区数据，红区数据就手动去识别化。另外，如果登录有问题，可以参考 [网页版登录排错](/posts/deepseek-web-login-troubleshoot/)。

**问：将客户资料改做「客户A」算不算足够？**

答：要看上下文。如果句子里面有「客户A在观塘买了500箱货」，仍然可能推断出身份。最好连地点、数量都模糊化，或者用本地模型做进阶去识别化。

**问：DeepSeek 有没有提供香港地区的数据储存选项？**

答：截至 2025 年 2 月，文档未见有香港专属数据中心选项，建议以文档为准。如果合约要求数据留在香港，本地 Ollama 方案会更稳阵。

**问：Prompt 里面不小心贴了敏感资料，可以怎么补救？**

答：立即在应用程序删除相关 log，并考虑旋转 API key。同时可以参考 [Prompt 基础教学](/posts/deepseek-prompt-basics/) 学习怎么用占位符代替真实数据。

## 总结

隐私清单不是要你放弃用 AI，而是帮你分清风险。我的经验是：绿区数据放胆用 DeepSeek 提升效率，黄区数据先去识别化，红区数据留在本地。做好这三步，香港中小企都可以安全地享受 AI 的好处。
