## 點解要比較呢兩隻模型？

上星期有個做貿易嘅朋友問我：「公司啲英文合同成幾十頁，仲有普通話錄音轉出嚟嘅文字稿，想搵個 AI 幫手摘要，DeepSeek 定 Gemini 好？」呢個問題好典型——香港人日常要處理中英夾雜、繁體簡體並存嘅文件，唔係是但揀隻模型就得。

我唔會講邊隻「全面勝出」，因為兩者喺唔同位置各有優勢。以下用我實際測試嘅經驗，同埋官方公開嘅版本資訊，幫你判斷邊隻更啱你嘅工作流。

## 我嘅測試設定（2025 年 2 月版）

我測試時用嘅係 DeepSeek V3（API 版本，2025 年 2 月公開預覽）同 Gemini 1.5 Pro（透過 Google AI Studio 使用）。測試材料有三份：

1. 一份 45 頁嘅英文採購合同（PDF 轉文字）
2. 一段 28 分鐘嘅廣東話會議錄音轉文字稿（約 6,000 字，有口語化表達）
3. 一份混雜繁體中文、簡體中文同英文嘅產品說明書

兩邊都係用預設溫度值，提示詞盡量保持一致，避免人為偏差。

## 三個維度打分：長文件摘要、多語言處理、香港場景實用性

### 維度一：長文件摘要（滿分 5 分）

- **DeepSeek V3：4 分。** 上下文窗口夠大，45 頁合同可以一次過餵入去，摘要結構清晰，會主動抽出「責任條款」「付款期限」呢類關鍵位。缺點係如果文件太長，偶爾會漏掉中間段落嘅細節，需要喺提示詞入面明確要求「逐段檢查」。
- **Gemini 1.5 Pro：4.5 分。** 原生支援超長上下文，摘要嘅連貫性稍勝一籌，尤其係處理圖表同文字混合嘅 PDF 時，提取表格數據嘅準確度較高。不過免費額度有限，大量處理要留意成本。

### 維度二：多語言處理（滿分 5 分）

- **DeepSeek V3：4 分。** 中英文切換流暢，繁體中文輸出自然，唔會無啦啦彈出簡體字。廣東話口語轉書面語嘅能力唔錯，但對於一啲香港特有詞彙（例如「搭棚」「放蛇」）嘅理解，偶然會偏離語境。
- **Gemini 1.5 Pro：3.5 分。** 英文同普通話處理好強，但繁體中文輸出有時會混入簡體字或者內地用語，需要後期人手校正。廣東話錄音轉文字後嘅摘要，佢傾向用書面語改寫，反而失去原意。

### 維度三：香港場景實用性（滿分 5 分）

- **DeepSeek V3：4.5 分。** API 定價相宜，適合中小企大量處理文件；可以透過 Ollama 做私有化部署，唔使擔心敏感資料外洩。如果你想知點樣喺本機架設，可以參考我之前寫嘅 [DeepSeek Ollama 本地安裝教學](/posts/deepseek-ollama-local-setup/)。
- **Gemini 1.5 Pro：3.5 分。** 網頁版操作簡單，但企業級應用要經 Google Cloud，設定門檻較高；而且數據會離開香港，對處理客戶合約嘅公司嚟講要審慎評估。

## 三步實操：點樣用 DeepSeek 做好長文件摘要？

如果你決定試 DeepSeek，以下係我常用嘅三步流程，跟住做可以減少「漏內容」嘅情況。

**第一步：用 API 定本機？先諗清楚。** 如果文件涉及客戶資料，建議用 Ollama 喺本機跑，詳情可睇 [本地部署步驟](/posts/deepseek-ollama-local-setup/)。如果只係一般參考資料，直接用 API 更方便。申請 API Key 同了解用量限制，可以睇 [API Key 與額度說明](/posts/deepseek-api-key-and-limits/)。

**第二步：撰寫有結構嘅提示詞。** 唔好淨係打「幫我摘要呢份文件」。我測試時發現，用以下格式效果最好：

你係法律文件助理。請閱讀以下合同，並輸出：
1. 雙方主要責任（列點）
2. 付款條款與期限
3. 違約條款嘅觸發條件
4. 任何需要香港法律角度留意嘅地方

合同內容：
[貼上文字]

想學更多提示詞技巧，可以參考 [提示詞基礎教學](/posts/deepseek-prompt-basics/)。

**第三步：分段覆核，唔好一次過信晒。** 就算模型話摘要完成，我都會抽樣對照原文，特別係數字同日期。如果 API 回傳錯誤碼（例如 429 代表請求過多），可以跟 [重試指南](/posts/deepseek-api-retry-guide/) 處理，唔使慌。

## 常見問題

**問：DeepSeek 同 Gemini 邊隻處理繁體中文好啲？**

答：以我測試嘅版本（DeepSeek V3 2025 年 2 月、Gemini 1.5 Pro）嚟講，DeepSeek 嘅繁體中文輸出較少混入簡體字，但實際表現可能隨版本更新而有變，以官方文檔為準。

**問：我公司得幾個人，用邊隻成本低啲？**

答：DeepSeek API 嘅定價一般較相宜，而且可以按用量付費；Gemini 有免費額度但超出後要留意收費。具體價格請以兩邊官方網站公佈為準。

**問：可唔可以兩隻一齊用？**

答：可以。有啲人會用 Gemini 做英文文件初稿，再用 DeepSeek 做繁體中文潤色。不過要留意資料傳輸同私隱問題，敏感文件建議只喺本機處理。

**問：點解我有時會見到 DeepSeek 回傳「模型繁忙」？**

答：呢個通常係伺服器負載問題，可以稍等再試，或者參考 [API 重試指南](/posts/deepseek-api-retry-guide/) 設定自動重試。

**問：邊度可以睇到最新版本資訊？**

答：建議直接去 DeepSeek 平台（platform.deepseek.com）查閱公告，唔好靠第三方轉載，以免資料過時。

## 總結俾香港用家嘅建議

如果你主要處理英文合同同普通話內容，Gemini 1.5 Pro 嘅長上下文連貫性幾好；但如果你需要繁體中文輸出穩定、想控制成本、甚至做私有化部署，DeepSeek V3 會更貼地。我嘅做法係：敏感文件用 DeepSeek 本機跑，一般資料用 API，兩者並行。記住，任何摘要結果都要人手覆核，唔好當佢係最終定稿。
