## 我为什么开了深度思考？

上个月升级了 DeepSeek 网页版（记得是 2025 年 1 月中的界面更新），看到「深度思考 (R1)」按钮，好奇就长开。结果问「明天香港天气怎么样？」它都跟我琢磨十几秒，还在答案前面加一大段「首先，我需要确定用户问的是哪个城市……」我真想跟它说：大佬，我问的是天气，不是哲学。

后来我测试时发现，R1 模式会强制模型输出推理链（reasoning chain），哪怕问题简单到只需一句答案，它也会先「想一轮」。这个设计原意是好的，但日常琐碎问题就变成用牛刀杀鸡。如果你只是想快速查资料、改文法、或者打招呼，其实关掉深度思考会顺畅很多。

## 实测：简单问题开 R1 的代价

我用同一个问题「香港哪间大学有图书馆 24 小时开放？」分别试了开和不开深度思考。不开那次，2 秒内出答案，直接列了几间大学的图书馆开放时间。开了 R1 那次，等了 11 秒，答案开头竟然是「用户可能想了解香港各大学图书馆的夜间开放情况，我需要先确认……」，然后才给答案。答案内容差不多，但多了一堆废话，还多吃几倍 token。

这里不是说 R1 不好。如果你问的是数学证明、复杂逻辑题、或者要逐步推导的东西，R1 真的帮到手。但对于「简单问题」，深度思考反而是负担。官方文档也写明 R1 适合「需要多步推理」的任务，一般查询用回普通模式就行（以官方文档为准）。

## 3 步关闭深度思考（以 2025 年 1 月版本为例）

如果你跟我一样，之前不小心开了 R1 长驻，可以跟着下面三步关掉：

1. **打开 DeepSeek 网页或 App**，在对话输入框上方找到「深度思考 (R1)」的 toggle 按钮。网页版通常在输入框左边；App 版在输入框下面。
2. **点击 toggle 按钮，让它变灰**。确认按钮上的文字从「深度思考中」变回「深度思考」，即代表已关闭。
3. **开新对话测试**。打一句「你好」或者「今天几号」，看看回复有没有再出现「首先，我需要……」的推理段落。如果没有，就代表成功关闭。

温馨提示：如果你用 API，就要在 request body 里不要加 `reasoning` 参数，或者将 `model` 从 `deepseek-reasoner` 转回 `deepseek-chat`。这点跟 [DeepSeek API 密钥与限额教学](/posts/deepseek-api-key-and-limits/) 里讲的 model 选择有关，有兴趣可以看看。

## 常见问题

**问：是不是所有简单问题都不应该开深度思考？**
答：不是绝对。如果你问的问题虽然短，但涉及多步计算或者需要核对多个条件，R1 可能帮到手。但对于纯查询、闲聊、改错字这类，关掉会快很多。

**问：关掉深度思考会不会影响答案准确度？**
答：对于简单问题，普通模式的准确度已经足够；R1 的优势在于复杂推理，简单问题开 R1 不会让答案更准，只会更慢和更长。

**问：我在 API 里怎么确保不用 R1？**
答：调用 API 时，将 `model` 设为 `deepseek-chat` 就是普通模式；如果用 `deepseek-reasoner` 就是 R1。详细参数可以参考 [DeepSeek API 重试指南](/posts/deepseek-api-retry-guide/)，里面有讲怎么避免不必要的推理开销。

**问：深度思考模式会不会影响数据安全？**
答：R1 模式会将推理过程都传送到服务器，如果你处理敏感资料，建议关掉深度思考，减少不必要的数据传输。想了解本地部署可以看 [Ollama 本地架设教学](/posts/deepseek-ollama-local-setup/)。

**问：怎么知道现在是不是开了深度思考？**
答：最简单是看回复有没有「思考过程」区块，或者输入框附近的 toggle 状态。如果不确定，开新对话问「1+1」，正常应该直接答「2」，不会长篇大论。

---

总的来讲，深度思考是一把好刀，但别什么都拿来切。简单问题，关掉 R1，省回自己时间。想知更多 prompt 技巧，可以参考 [DeepSeek Prompt 基础教学](/posts/deepseek-prompt-basics/)。
