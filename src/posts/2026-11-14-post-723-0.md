## 點解揀 Function Calling 整天氣機械人

上星期我想試吓 DeepSeek API 嘅 Function Calling，唔想淨係寫個「你好」demo，於是揀咗天氣查詢做實例。原因好簡單：天氣數據要實時，模型自己答唔到，一定要 call 外部 API，正好示範工具調用嘅完整流程。

我用嘅係 `deepseek-chat` 模型，根據 [官方 API 文檔](https://platform.deepseek.com) 嘅說明，Function Calling 喺 2024 年底已經支援，請求格式跟 OpenAI 兼容。價錢方面，以官方公佈為準，我測試嗰陣輸入輸出都係按 token 計，好平。

## 第一步：攞 API Key 同揀模型

去 platform.deepseek.com 註冊，入去「API Keys」頁面撳「Create new key」，複製個 key 出嚟。記得唔好直接寫入代碼，用環境變數存。

```bash
export DEEPSEEK_API_KEY="sk-你個key"
```

跟住裝 OpenAI Python SDK，因為 DeepSeek 嘅接口兼容，直接改 base_url 就得：

```python
from openai import OpenAI
client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com"
)
```

呢步冇乜難度，但如果之前未用過 DeepSeek，可以睇吓 [API Key 同額度限制嘅整理](/posts/deepseek-api-key-and-limits/)，入面講咗免費額度同 rate limit 嘅細節。

## 第二步：定義天氣工具同寫 system prompt

Function Calling 嘅核心係喺請求入面加 `tools` 參數，話俾模型知有咩工具可以用。我定義咗一個 `get_weather` 函數，參數係城市名：

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查詢指定城市嘅即時天氣",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名，例如香港"}
            },
            "required": ["city"]
        }
    }
}]
```

System prompt 我寫得好直白：「你係天氣助手，用戶問天氣時必須調用 get_weather 工具，唔好自己估。」

呢度有個位要留意：description 寫得越清楚，模型越少亂 call。我試過求其寫「查天氣」，結果模型有時會直接答「今日晴」，完全冇 call 工具。

## 第三步：處理 tool_calls 回傳同第二輪請求

發送第一輪請求之後，模型唔會直接答天气，而係回傳一個 `tool_calls` 陣列，入面有函數名同參數。你要自己執行嗰個函數，再將結果塞返去對話歷史，發第二輪請求。

```python
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "香港今日天氣點？"}],
    tools=tools
)

tool_call = response.choices[0].message.tool_calls[0]
args = json.loads(tool_call.function.arguments)
weather_data = get_weather(args["city"])  # 你嘅真實函數

messages = [
    {"role": "user", "content": "香港今日天氣點？"},
    response.choices[0].message,
    {"role": "tool", "tool_call_id": tool_call.id, "content": json.dumps(weather_data)}
]

final = client.chat.completions.create(
    model="deepseek-chat",
    messages=messages,
    tools=tools
)
```

第二輪請求一定要帶返 `tool_call_id`，否則會出 400 錯誤。我第一次漏咗，搞咗十分鐘先發現。

## 我實測時遇到嘅三個伏位

第一個伏位係 `finish_reason`。有時模型回傳 `tool_calls`，但有時會直接答文字，你要檢查 `response.choices[0].finish_reason` 係咪 `"tool_calls"`，唔好假設一定有。

第二個伏位係 timeout。天氣 API 如果慢，成個請求會拖長，我試過等咗 30 秒。建議喺 client 加 `timeout=15`，再配 [重試機制](/posts/deepseek-api-retry-guide/) 處理 429 或 5xx 錯誤。

第三個伏位係參數類型。模型有時會將城市名包成 `{"city": "香港"}`，但有時會多層嵌套，最好喺函數入面做防禦性解析。

## 常見問題

**Q1：Function Calling 使唔使額外收費？**
以官方文檔為準，工具定義會計入輸入 token，調用結果都係 token 計費，冇額外功能費。

**Q2：可唔可以同時定義多個工具？**
可以，`tools` 係陣列，模型會自己揀。但工具太多會增加混淆，建議唔好超過 5 個。

**Q3：點解模型唔 call 工具，直接答我？**
多數係 prompt 唔夠明確，或者工具 description 太模糊。試吓喺 system prompt 加「必須使用工具」嘅指令。

**Q4：本地用 Ollama 跑得到嗎？**
Ollama 嘅模型對 Function Calling 支援程度不一，想試本地可以參考 [Ollama 本地設置教學](/posts/deepseek-ollama-local-setup/)，但複雜工具調用建議都係用 API。

**Q5：報錯 `invalid tool_call_id` 點算？**
檢查你回傳嘅 `tool_call_id` 係咪同模型回傳嗰個完全一致，包括大小寫。
