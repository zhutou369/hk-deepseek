## 我怎么开始用 DeepSeek 写公式

上个月我帮一家做零售的中小企业整理销售报表，他们之前用人手筛选，每次复核都要半小时。我试着用 DeepSeek（当时网页版界面显示的模型版本是 DeepSeek-V2，以官方文档为准）帮忙写几条公式，结果发现：**问题问得不好，出来的公式多半要改**。

比如你直接打“帮我写条加总公式”，它会回你 `=SUM(A1:A10)`，但如果你数据有隐藏列、或者要按条件加总，这条公式就不够用。所以我之后转了一套提问方式，出错率明显低了。

## 三个步骤：从描述到可用公式

### 第一步：讲清楚你的数据长什么样

别只说“我有个表”，要讲清楚列名和范围。比如：

> “A 列是日期（2024/01/01 格式），B 列是产品名，C 列是数量，D 列是单价。我想在 E 列算每行的总价。”

这样 DeepSeek 就会给你 `=C2*D2`，而不会乱猜。

### 第二步：用“如果……就……”讲条件

Excel 公式最常出错的地方就是条件判断。我习惯用口语讲清楚逻辑，比如：

> “如果 C 列大于 10，就在 F 列显示‘大批’，否则显示‘小批’。”

对应公式就是 `=IF(C2>10,"大批","小批")`。如果涉及多个条件，就逐个列出，别一句话带过。

### 第三步：要求它解释公式怎么运作

这一步很重要。我会加一句：“请解释这条公式每个部分的作用，以及有没有哪种情况会出错。”这样你不止拿到公式，还学到怎么调试。

## 我测试时发现的提问细节

上周我升级了 DeepSeek 网页版（具体版本号以官方公布为准），试了同一个问题问三次，发现以下几点：

1. **讲明 Excel 版本**：如果你用 Excel 2016 或以上，可以讲“我用 Excel 2021”，它会避免用太新的函数（比如 `XLOOKUP` 在旧版没有）。
2. **避免简写**：别写“sumif 条件”，要写“按 B 列等于‘香港’加总 C 列”。
3. **要求输出纯公式**：有时它会加上解释，你可以讲“只输出公式，不要解释”，方便直接复制。

另外，如果你要处理敏感数据，记得别直接贴客户资料上网。可以考虑用本地部署，比如参考[DeepSeek Ollama 本地安装教学](/posts/deepseek-ollama-local-setup/)，这样就不用经过网络传输。

## 常见问题

**Q1：DeepSeek 写的公式对不对？**

大部分常用函数（SUM、IF、VLOOKUP、SUMIFS）都准确，但复杂的数组公式或动态数组就要自己验证。建议先在备份文件试。

**Q2：为什么它有时会给错单元格范围？**

因为你没讲清楚数据从第几行开始。提问时加一句“数据从第 2 行开始，标题在第 1 行”就可以避免。

**Q3：可不可以叫它一次写多条公式？**

可以，但建议分开问。每条公式独立提问，出错时容易追。如果想了解提问结构，可以看[DeepSeek 提问基础技巧](/posts/deepseek-prompt-basics/)。

**Q4：用 API 还是网页版好？**

如果只是偶尔写公式，网页版免费又够用。如果要批量处理或整合到公司系统，就要用 API，记得留意[API Key 与用量限制](/posts/deepseek-api-key-and-limits/)。

**Q5：公式出错有没有办法叫它调试？**

有。你可以贴回错误信息（比如 `#VALUE!`）和你那条公式，叫它解释为什么会这样。如果是 API 报错，可以参考[重试机制指南](/posts/deepseek-api-retry-guide/)。

## 小结

用 DeepSeek 写 Excel 公式，关键不是模型有多强，而是你怎么描述问题。我的经验是：**讲清楚列、条件、版本，再叫它解释**，这样出来的公式十条有八条可以直接用。剩下两条，多半是自己数据格式不统一，清理完就没事了。
