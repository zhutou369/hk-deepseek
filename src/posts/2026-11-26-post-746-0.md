上週我用 DeepSeek 嘅 API（當時用嘅版本係 1.3，以官方文檔為準）幫一間香港中小企清洗咗 800 條客戶名單。佢哋原本嘅 Excel 亂到七彩：電話有空格同加號、公司名有全形半形混雜、重複記錄至少 30 條。我測試時發現，如果用本地模型跑，速度慢而且格式化唔穩定；轉用 API 之後，一次過處理 200 條，大約 40 秒搞掂。

![DeepSeek 批次處理客戶名單的工作流程示意](/static/images/photo-1531746790731-6c087fecd65a.jpg)

## 第一步：準備 CSV 與設定 API

先將客戶名單匯出做 CSV，確保有最少三欄：姓名、電話、公司。我習慣用 UTF-8 編碼，避免中文亂碼。然後去 platform.deepseek.com 開一個 API key，免費額度足夠試 1000 條左右。如果你未用過 API，可以參考站內嘅 [DeepSeek API Key 申請與用量限制](/posts/deepseek-api-key-and-limits/) 教學。

我用 Python 寫咗個簡單腳本，將 CSV 逐行轉做 JSON，每 50 條做一批，然後 call API。記住要設定 timeout 同重試機制，避免網絡唔穩定時中斷。詳細重試寫法可以睇 [DeepSeek API 重試指南](/posts/deepseek-api-retry-guide/)。

## 第二步：用提示詞做去重與格式化

呢步最關鍵。我嘅提示詞係咁寫（繁體中文，但叫模型輸出英文欄位名方便匯入）：

> 你係數據清洗助手。下面係一批客戶記錄，每條有姓名、電話、公司。請完成：1. 刪除完全重複嘅記錄（姓名+電話相同）；2. 將電話格式化為「+852 XXXX XXXX」；3. 公司名統一把「有限公司」轉做「Ltd.」；4. 輸出 JSON 陣列，欄位為 name、phone、company。只輸出 JSON，唔好解釋。

我測試時發現，如果唔指定「只輸出 JSON」，模型會加一堆廢話。另外，電話格式化要講明香港區號，否則有時會漏咗 +852。提示詞嘅基本結構可以參考 [DeepSeek 提示詞入門](/posts/deepseek-prompt-basics/)，入面有講點樣用 system prompt 鎖定輸出格式。

![使用 DeepSeek 提示詞進行客戶名單去重與格式化的畫面](/static/images/photo-1607604276583-eef5d076aa5f.jpg)

每批處理完之後，我會用簡單嘅 Python 腳本合併結果，再做一次本地去重（用 set 比對電話），確保冇漏網之魚。

## 第三步：匯出並匯入 CRM

將清洗好嘅 JSON 轉返 CSV，欄位對應你嘅 CRM（例如 HubSpot、Zoho 或者自建系統）。我通常會保留一個「備註」欄，寫低原始數據有冇被修改，方便日後審計。匯入之前，最好用 CRM 嘅預覽功能檢查電話格式同公司名。如果 CRM 要求電話必須有區號，我哋嘅 +852 格式就啱用。

匯入之後，檢查有冇重複創建聯絡人。我試過因為電話格式唔一致，CRM 當咗兩個唔同嘅人。解決方法係匯入前用 CRM 嘅去重規則再跑一次。

## 常見問題

**問：DeepSeek API 處理 1000 條名單要幾耐？**
答：以我實測，每批 50 條、共 20 批，大約 6 至 8 分鐘，視乎網絡同 API 負載。建議分批處理，唔好一次過丟太多。

**問：免費額度夠唔夠用？**
答：新註冊有免費 token 額度，處理幾千條一般夠用。詳細額度以官方文檔為準。

**問：可唔可以喺本地跑，唔用 API？**
答：可以，用 Ollama 加載 DeepSeek 模型，適合數據敏感嘅公司。設定方法睇 [DeepSeek Ollama 本地安裝](/posts/deepseek-ollama-local-setup/)。不過本地模型速度較慢，格式化穩定性都要自己試。

**問：提示詞入面使唔使加「香港」？**
答：要，尤其係電話同公司名格式。加「香港」可以減少模型用內地格式嘅機會。

**問：匯入 CRM 後發現有錯點算？**
答：保留原始 CSV 同清洗後嘅 JSON，可以隨時重跑。建議每次匯入前備份 CRM 數據。
