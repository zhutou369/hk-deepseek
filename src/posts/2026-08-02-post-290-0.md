## DeepSeek 上下文「聰明」剪裁，到底怎麼玩？

所謂「聰明」剪裁，不是簡單刪字，而是一套綜合策略，包含提示詞設計、API 參數調校和前後處理。核心就是提高信息密度，讓模型只處理關鍵訊息，過濾掉「噪音」。

### 第一招：提示詞要精準，讓 DeepSeek 乖乖聽你的！

提示詞是你和 DeepSeek AI 溝通的橋樑。寫得好，模型效率和輸出質量都會大幅提升。這是上下文剪裁的第一步，也是最關鍵的一步。想打好基礎，推薦看這篇：[DeepSeek 提示詞基本功](/posts/deepseek-prompt-basics/)！

1.  **砍掉廢話，直奔主題！** 寫提示詞別客套，直接甩問題和指令。比如，要總結文章，直接說「請總結以下文章：[文章內容]」，別繞彎子。節省 Token 從這裡開始！
2.  **用 `system` message 給 AI 安排「角色」！** `system` message 能設定模型的「人設」和行為規矩。你可以告訴它：「你現在是個專業的市場分析師，只提供客觀數據和簡潔分析，禁止發表個人意見。」模型就會自動過濾冗餘信息，專心幹活。
3.  **明確告訴 AI 你想要什麼格式和長度！** 比如「請用三點式總結，每點不超過 50 字」，或者「請以 JSON 格式返回產品信息：{“名稱”: “”, “價格”: “”}」。指令越具體，模型給出的結果就越精準簡潔。

### 第二招：API 參數微調，讓 DeepSeek 「見好就收」！

DeepSeek API 參數是控制模型行為的神兵利器，對上下文剪裁尤為重要。

1.  **`max_tokens`：給 AI 輸出「設個限」！** 直接限制模型輸出長度。只想要簡短答案或摘要，就把 `max_tokens` 調小（如 100-200）。模型達到上限即停止，省錢省時間。當然，太短可能導致內容不完整，需權衡。
2.  **`temperature` 和 `top_p`：控制 AI 是「一本正經」還是「天馬行空」！** 這些參數控制模型生成文本的隨機性。我測試時發現，將 `temperature` 設定在 0.5 以下，DeepSeek 模型會更傾向於提供直接、不繞彎的答案，尤其在處理技術支援查詢時，能顯著減少冗餘內容，節省 Token 和時間。這對於需要準確、簡潔信息的香港中小企非常適用！調整 `top_p` 也有助於聚焦。更詳細用法，請參考 [DeepSeek API 參數詳解](/posts/deepseek-api-parameters-guide/)。
3.  **`stop` sequences：給 AI 畫條「終止線」！** 設定特定字符，當模型生成到這些字符時便停止輸出。例如，要模型寫完一個段落就停，可設置 `stop=["\n\n"]`。這比單純依賴 `max_tokens` 更智能，適合精確控制輸出結束點的場景。

### 第三招：數據預處理和後處理，給 AI 餵「精華」！

我們給 DeepSeek 模型的數據常帶「雜質」。提前清理或後期加工，能大大減少 Token 浪費。

1.  **輸入數據的精簡與歸納**：傳給 DeepSeek 前，先手動過濾不相關信息（如導航、廣告）。對超長文檔，可先用關鍵詞提取或輕量級模型做初步摘要。只把最核心數據傳給 DeepSeek 深度處理，既省 Token 又讓其更專注。
2.  **輸出結果的篩選與修剪**：即使設了 `max_tokens` 和 `stop` sequences，模型仍可能多說幾句。收到輸出後，可用腳本或規則二次處理，剔除冗餘開場白、結尾語或格式錯誤。比如，去除「好的，這是您請求的總結：…」。
3.  **分批處理長文本**：超長文本單次傳入可能超限或費用過高。可切分成小塊分別處理，再匯總輸出。這需要巧妙設計，避免語義缺失。對於複雜任務，建議設計一個健壯的 [DeepSeek 工作流自動化方案](/posts/deepseek-workflow-automation/)，確保效率和準確性。

## 常見問題解答 (FAQ)

DeepSeek 上下文剪裁過程中，大家常有疑惑。我整理了幾個，希望能幫你！

### Q1: 剪裁過度會不會影響 DeepSeek 的理解能力？

**A:** 當然會！「聰明」剪裁是提高信息密度，不是亂刪。如果把關鍵信息剪掉，模型自然無法正確理解。剪裁時務必謹慎，確保留下的是對模型決策至關重要的信息。我的經驗是，先保守剪裁，逐步加大力度，同時觀察輸出質量，找到最佳平衡點。省錢歸省錢，效果還是要保證的嘛！

### Q2: 怎麼判斷哪些信息是「冗餘」的？

**A:** 判斷冗餘信息有跡可循。重複語句、過多客套話、不相關背景介紹、可省略的連接詞等，都是可考慮剪裁的。你可以想像：這句話去掉，人類讀者還能完全理解嗎？如果能，那對 AI 模型來說，它很可能也是「非必要」的。服務於目標之外的信息，都可視為冗餘。

### Q3: DeepSeek API 有哪些限制，會影響我的剪裁策略嗎？

**A:** DeepSeek API 有上下文窗口最大長度、RPM、TPM 等限制。這些硬性限制會直接影響你的剪裁策略。例如，輸入加輸出超過單次請求上下文限制，就必須更大力度剪裁或分塊處理。為了避免踩坑，建議仔細閱讀 DeepSeek 官方文檔，了解最新的 [DeepSeek API 費用與限制](/posts/deepseek-api-key-and-limits/)，做到心中有數。這樣才能更好地規劃剪裁方案，既省錢又高效。
