## 點解要睇量化版本先買卡

上週幫一間中小企睇本地 AI 方案，對方第一句就問：「買張 RTX 4090 係咪就跑到 DeepSeek 70B？」我答：跑到，但要看量化。同一個模型名，Q4 同 Q8 的VRAM需求可以差一倍以上，跑不動多數不是卡太弱，而是選錯量化版本。

Ollama 的好處是幫你處理模型下載與推理後端，但佢不會幫你變出 VRAM。所以這篇集中講一件事：**不同量化版本的顯示卡門檻**。以下數字基於 2024 年 12 月時 Ollama 公開模型庫與社群實測，僅供參考，實際以官方文檔為準。

## 實測環境與版本

我測試時用 Ollama 0.5.x（2024 年 12 月版本），系統是 Ubuntu 22.04，顯示卡分別試過 RTX 3060 12GB、RTX 4090 24GB 同 RTX A6000 48GB。DeepSeek 模型則用 Ollama 模型庫的 `deepseek-r1` 系列，量化標籤以 `:7b`、`:14b`、`:32b`、`:70b` 加上 `q4_K_M`、`q8_0` 等後綴區分。

要留意：Ollama 預設拉下來的多數是 Q4_K_M 量化，想跑更高精度要自己指定 tag。另外，推理時 context 長度會額外佔 VRAM，以下門檻以 4K context 為基準，開到 32K 要再加。

## 不同量化版本的顯示卡門檻表

以下用「模型大小 × 量化」粗估 VRAM 門檻，數值取整到常見顯示卡容量：

| 模型 | 量化 | 約需 VRAM | 建議顯示卡 |
|---|---|---|---|
| DeepSeek 7B | Q4_K_M | 6–8GB | RTX 3060 12GB |
| DeepSeek 7B | Q8_0 | 10–12GB | RTX 3060 12GB（剛好） |
| DeepSeek 14B | Q4_K_M | 10–12GB | RTX 3060 12GB |
| DeepSeek 14B | Q8_0 | 18–20GB | RTX 4090 24GB |
| DeepSeek 32B | Q4_K_M | 20–24GB | RTX 4090 24GB |
| DeepSeek 32B | Q8_0 | 36–40GB | RTX A6000 48GB |
| DeepSeek 70B | Q4_K_M | 40–48GB | RTX A6000 48GB 或雙卡 |
| DeepSeek 70B | Q8_0 | 75GB+ | 多卡或 CPU+GPU 混合 |

表中「約需 VRAM」是把權重、KV cache 同推理開銷加起來的粗估。我實測 32B Q4_K_M 在 24GB 卡上跑 4K context 勉強夠，開到 8K 就開始爆 VRAM，會跌落 CPU 變慢。所以如果你要長上下文，建議直接跳一級顯示卡。

中小企常見做法是：7B/14B Q4 跑在單張 12GB 卡，用嚟做內部問答或文件摘要；32B 以上才考慮 24GB 卡。想知 API 同本地部署點揀，可以睇[DeepSeek API 金鑰與額度說明](/posts/deepseek-api-key-and-limits/)。

## 三步用 Ollama 跑起 DeepSeek

**第一步：安裝 Ollama 並確認顯示卡被認到**

到 ollama.com 下載對應系統安裝包，裝完開 terminal 打 `ollama --version`。然後跑 `ollama run deepseek-r1:7b`，首次會自動拉模型。如果想確認有無用 GPU，可以睇 Ollama 啟動 log，或者用 `nvidia-smi` 睇 VRAM 有無被佔用。

**第二步：按 VRAM 揀量化 tag**

不要盲目拉最大模型。12GB 卡就揀 `deepseek-r1:14b-q4_K_M` 或 `deepseek-r1:7b-q8_0`；24GB 卡可以試 `deepseek-r1:32b-q4_K_M`。拉錯 tag 最常見的報錯是 `out of memory`，見到就降一級量化或換細模型。

**第三步：限制 context 長度避免爆 VRAM**

Ollama 可以用 `OLLAMA_NUM_PARALLEL` 同 context 參數控制資源。簡單做法是在 Modelfile 或 API 呼叫時設 `num_ctx`，例如 4096。跑長文件時逐步加，唔好一次開到 32768。我測試時發現，32B Q4 在 24GB 卡開 8K context 已經會踩界，所以長文處理建議用 RAG 分段，相關做法可參考[DeepSeek 提示詞基礎教學](/posts/deepseek-prompt-basics/)。

## 常見問題

**Q1：VRAM 唔夠會點？**

Ollama 會嘗試把部分層跌落 CPU，速度明顯變慢，但未必直接報錯。如果連 CPU 都唔夠 RAM，就會出現 `out of memory` 或模型載入失敗。

**Q2：Q4 同 Q8 準確度差幾多？**

量化會影響輸出品質，但實際差距要看任務。一般問答 Q4_K_M 已經夠用；如果要處理程式碼或精細推理，可以試 Q8，但 VRAM 門檻高很多。具體效果以官方文檔及你自己的測試為準。

**Q3：Mac 機跑唔跑得？**

Apple Silicon 用統一記憶體，Ollama 有支援。M2 Pro 16GB 大約跑到 7B Q4；32GB 以上可以試 14B Q4。不過統一記憶體同獨立顯示卡的頻寬唔同，速度要實測。

**Q4：可唔可以兩張卡一齊跑？**

Ollama 支援多 GPU，但要看後端同驅動。70B Q4 用雙 24GB 卡有機會，但要設定 tensor split，細節以官方文檔為準。

**Q5：點解我拉到模型但跑得好慢？**

先睇 `nvidia-smi` 確認 VRAM 有無用盡。如果 VRAM 滿但 GPU 使用率低，多數是模型部分跌落 CPU，或者 context 太長。試下換細一級量化，或者參考[Ollama 本地部署教學](/posts/deepseek-ollama-local-setup/) 檢查設定。

最後提醒：以上門檻表是 2024 年 12 月的粗估，Ollama 與 DeepSeek 模型庫更新好快，買卡前最好用 `ollama show` 睇實際模型大小，再以官方文檔為準。
