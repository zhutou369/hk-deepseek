## 點解要理 Token 計費？

上個月幫一間做網購嘅香港中小企睇 API 帳單，佢哋用 DeepSeek 做客服自動回覆，本來以為「用量唔多」，結果月尾張單比預算多咗四成。唔係 DeepSeek 收貴咗，而係佢哋冇為「輸出 token」同「對話歷史」做預算。

DeepSeek 嘅 API 收費係按 token 計，輸入同輸出分開定價，而且每次請求都會將成段對話歷史（包括 system prompt、之前嘅 user 同 assistant 訊息）一齊計入輸入 token。呢點同好多人以為「按訊息數收費」嘅直覺好唔同，亦係帳單失預算嘅常見原因。

呢篇會用一個具體場景，逐步拆解點樣由「每日對話量」推算到「每月港幣支出」，等你可以喺寫 code 之前就心裏有數。

## Token 係咩？同中文字數點換算？

Token 係模型處理文字嘅基本單位，可以理解為「字詞碎片」。英文一個 token 大約等於 0.75 個單詞；中文方面，以官方文檔嘅說法，一個中文字大約對應 0.6 至 1 個 token，實際取決於分詞方式。保守起見，預算時可以當「1 個中文字 ≈ 1 token」嚟計，寧願估多好過估少。

要留意嘅係，DeepSeek 嘅 API 定價會隨版本更新，我測試時參考嘅係 2025 年 2 月公開嘅價格表（具體數字以官方文檔為準）。當時嘅收費邏輯係：輸入 token 同輸出 token 分開計，輸出通常貴過輸入，所以長回覆係成本大戶。

另外，如果你用嘅係 `deepseek-chat` 模型，佢有上下文長度上限，超過就會報錯。想避免觸發限流或超額，可以參考站內另一篇講 [API Key 同用量限制](/posts/deepseek-api-key-and-limits/) 嘅文章，入面有講點樣睇 dashboard 同設定警報。

## 實例：香港中小企 AI 客服每月帳單預估

假設你經營一間網店，用 DeepSeek API 做 AI 客服，每日大約有 300 個用戶查詢，每個查詢來回 3 輪對話。我哋逐項拆開：

**1. 每次請求嘅輸入 token**

- System prompt（客服角色設定、店鋪政策）：約 200 字 → 200 token
- 對話歷史：每輪 user 訊息約 30 字、assistant 回覆約 80 字，3 輪累計約 330 token
- 今次用戶訊息：約 30 token
- 合計輸入：約 560 token／次

**2. 每次請求嘅輸出 token**

- 客服回覆約 120 字 → 保守當 120 token

**3. 每日 token 總量**

- 每個查詢 3 輪，即 3 次 API 請求
- 每日請求數：300 × 3 = 900 次
- 每日輸入 token：900 × 560 ≈ 504,000
- 每日輸出 token：900 × 120 ≈ 108,000

**4. 每月（以 30 日計）**

- 輸入：約 1,512 萬 token
- 輸出：約 324 萬 token

跟住將呢兩個數字乘返官方單價（記得用最新價格表），就可以得出每月成本。以我測試時嘅價格水平粗略估算，呢個規模嘅客服系統，每月 API 支出大約係幾百港幣級別——具體數字會隨官方定價調整，建議你直接喺 platform.deepseek.com 嘅定價頁面用最新數字代入。

## 3 步實操：由測試到預估

**第一步：用真實對話做一次 token 實測**

唔好靠估。揀 10 段真實客服對話，逐段掉入 API（或者用官方 playground），睇回應入面 `usage` 欄位嘅 `prompt_tokens` 同 `completion_tokens`。將 10 段嘅平均值乘返你嘅每日請求數，呢個係最貼近現實嘅基數。

**第二步：計埋「對話歷史膨脹」**

好多人只計單次訊息，忽略咗每輪對話都會將之前嘅內容重新送入模型。你可以喺 code 入面設定「只保留最近 N 輪歷史」，例如 N=5，咁輸入 token 就唔會無限膨脹。呢個做法同時可以減少 [API 重試](/posts/deepseek-api-retry-guide/) 時嘅重複成本。

**第三步：設預算警報同每月覆核**

喺 platform.deepseek.com 嘅用量頁面設定每月支出上限通知。我習慣每月第一個禮拜覆核一次：對比實際 token 用量同預估數字，如果偏差超過 20%，就檢查係咪有 prompt 改動、回覆變長、或者對話歷史冇截斷。

順帶一提，如果你用嘅係 [Ollama 本地部署](/posts/deepseek-ollama-local-setup/)，就唔係按 token 收費，而係食你部機嘅顯示卡資源，成本結構完全唔同，適合用量穩定但唔想俾月費嘅團隊。

## 常見問題

**Q1：點解我嘅帳單比預估多好多？**

最常見原因係輸出 token 失控——回覆太長、或者冇設定 `max_tokens` 上限。其次係對話歷史冇截斷，每次請求都將全部舊訊息送入去。建議先睇 usage 明細，分清輸入同輸出邊邊佔比高。

**Q2：Token 數量同中文字數係咪一對一？**

唔係。官方文檔講明中英文分詞方式唔同，一個中文字可能對應少於一個 token，但保守預算時當一對一會安全啲。實際數字以 API 回應嘅 `usage` 欄位為準。

**Q3：Cache 有冇得慳錢？**

DeepSeek 有提供上下文緩存機制，重複嘅前綴內容有機會以較低價格計費。具體折扣同觸發條件以官方文檔為準，唔好假設一定有。

**Q4：點樣避免突然爆額？**

設定每日或每月用量上限，同埋喺 code 入面加 `max_tokens` 同對話輪數限制。另外可以參考 [提示詞基礎](/posts/deepseek-prompt-basics/) 嘅文章，用更精簡嘅 system prompt 減少固定輸入成本。

**Q5：免費額度用完會點？**

免費額度耗盡後，API 請求會返回餘額不足相關錯誤碼。如果你係用 web 版登入遇到問題，可以睇 [登入排錯指南](/posts/deepseek-web-login-troubleshoot/)。API 嘅具體錯誤碼同處理方式，以官方文檔為準。
