## 為何要將 DeepSeek 本地化？

中小企用生成式AI，最常煩惱的就是數據安全、合規要求和成本。DeepSeek模型本地化，就是把數據處理放到公司自己的伺服器上，這些問題一下子就能解決大半。舉個例子，像金融、醫療或法律這些行業，數據都受《個人資料（私隱）條例》這類嚴格法規管著，本地部署就能讓你對數據有更強的掌控力。而且，雲端API一直用會累積一筆不小的費用，本地部署前期投入硬件，但長期算下來，往往更划算。

我在測試DeepSeek Coder 33B Instruct模型時，發現其在本地運行的表現非常出色，特別是當前Ollama最新版本（以2024年6月的v0.1.34為例）對模型支援及GPU優化更為成熟，實測回應速度與準確性都令人滿意，足以應付一般的開發輔助、文件摘要、客戶服務等場景。說白了，數據放自己家裡，安全感不是一般的好。

## 環境準備：硬件與軟件清單

想讓DeepSeek跑得溜？那伺服器配置得跟上，建議這些：

*   **處理器 (CPU)**：Intel i7 或 AMD Ryzen 7 以上，或者同等級伺服器CPU。
*   **記憶體 (RAM)**：至少 32GB，如果多模型多用戶同時跑，建議 64GB 或更多。
*   **顯示卡 (GPU)**：這玩意兒是核心！推薦一張或多張 NVIDIA RTX 系列卡，VRAM 至少 12GB。像 RTX 3060 12GB、RTX 3090、RTX 4090 都行。VRAM越大，能加載的模型越大，跑起來越順。
*   **儲存空間**：SSD 固態硬碟是必須的，至少 500GB，裝系統、Ollama 和模型文件，讀寫速度才夠快。
*   **操作系統**：Ubuntu Server (推薦，22.04 LTS 或更新) 或 Windows Server。

軟件方面，主要會用到：

*   **Ollama**：開源的本地LLM運行框架，安裝模型超級方便。直接去 [Ollama 官方網站](https://ollama.com/) 下載安裝就行。
*   **Docker/Podman**：把不同用戶的 DeepSeek 實例容器化，實現權限隔離就靠它了。
*   **Nginx 或 Caddy**：搞反向代理，負責用戶身份驗證和流量分發。

## DeepSeek本地化搭建三步曲

### 第一步：Ollama與DeepSeek模型部署

首先，我們得把 Ollama 裝好，然後下載 DeepSeek 模型。如果你伺服器是 Ubuntu，裝 Ollama 超簡單，在終端機敲這行命令就行：

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

裝好後，就可以拉 DeepSeek 模型了。DeepSeek 有好多尺寸的模型，比如 `deepseek-coder:33b-instruct` 或 `deepseek-llm:67b-chat`。根據你的顯示卡VRAM情況來選：

```bash
ollama pull deepseek-coder:33b-instruct
```

這過程可能要等一會兒，看你網速和模型大小了。拉下來後，運行 `ollama run deepseek-coder:33b-instruct` 就能測試模型是否正常。Ollama 的詳細設定，可以參考這篇教學：[DeepSeek模型與Ollama本地部署教學](/posts/deepseek-ollama-local-setup/)。

### 第二步：多用戶環境與權限隔離配置

想搞多用戶權限隔離？最靠譜的辦法就是給每個用戶或組單獨開一個 DeepSeek/Ollama 容器實例，然後用反向代理來管訪問。我們可以用 Docker Compose 來管理這些容器，方便得很。

建一個 `docker-compose.yml` 文件，內容大概這樣：

```yaml
version: '3.8'
services:
  deepseek-user1:
    image: ollama/ollama
    container_name: deepseek-user1
    hostname: deepseek-user1
    restart: always
    ports:
      - "127.0.0.1:11434:11434" # 內部服務映射到本地環回地址
    volumes:
      - ./ollama_data_user1:/root/.ollama # 用戶1獨立儲存模型與數據
    environment:
      - OLLAMA_HOST=0.0.0.0
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1 # 為此實例分配一個GPU，多個GPU可指定ID
              capabilities: [gpu]

  deepseek-user2:
    image: ollama/ollama
    container_name: deepseek-user2
    hostname: deepseek-user2
    restart: always
    ports:
      - "127.0.0.1:11435:11434" # 用戶2映射到不同端口
    volumes:
      - ./ollama_data_user2:/root/.ollama # 用戶2獨立儲存模型與數據
    environment:
      - OLLAMA_HOST=0.0.0.0
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

# ... 依需要添加更多用戶實例
```

這裡關鍵是每個用戶的 `ollama_data_userX` 目錄都是獨立的，確保各自的模型、緩存和設置互不干擾。同時，通過 `ports` 映射到不同的本地端口。如果有多張顯示卡，可以在 `devices` 下精確指定 GPU 的 ID。

接下來，用 Nginx 做反向代理，再加個基礎認證（Basic Auth）。在 Nginx 配置裡，給每個用戶建一個 `server` 區塊，用 `auth_basic` 和 `auth_basic_user_file` 定義用戶名密碼：

```nginx
server {
    listen 80;
    server_name user1.deepseek.yourcompany.com;

    location / {
        proxy_pass http://127.0.0.1:11434;
        auth_basic "Restricted Access";
        auth_basic_user_file /etc/nginx/conf.d/deepseek_user1.htpasswd;
        # ... 其他proxy設置
    }
}

server {
    listen 80;
    server_name user2.deepseek.yourcompany.com;

    location / {
        proxy_pass http://127.0.0.1:11435;
        auth_basic "Restricted Access";
        auth_basic_user_file /etc/nginx/conf.d/deepseek_user2.htpasswd;
        # ... 其他proxy設置
    }
}
```

每個 `.htpasswd` 文件只放對應用戶的加密密碼，這樣用戶之間的訪問權限就隔離開了。你可以用 `htpasswd -c deepseek_user1.htpasswd user1` 來創建這些密碼文件。

### 第三步：內網存取與監控優化

DeepSeek 和權限都配好後，下一步就是保證它在公司內網能安全穩定訪問。你可以給 `user1.deepseek.yourcompany.com` 這類域名在內部 DNS 服務器上指向你 DeepSeek 伺服器 IP，或者直接用 IP 和端口號訪問，但域名方式看起來更專業好記。為了用起來更舒服，建議裝個 Web UI，比如 `Ollama Web UI` 或 `NextChat`，把它們也容器化，通過 Nginx 反向代理到各自的 DeepSeek 實例。

還有，系統監控非常重要，要定期看 GPU 使用率、記憶體消耗、網絡流量還有 DeepSeek 容器的運行狀態。你可以用 Prometheus 和 Grafana 搭一套監控系統，實時追蹤資源，早發現早解決潛在問題。例如，當我發現某個用戶的請求導致 GPU 記憶體長期處於高位時，會考慮調整他能加載的模型大小或者直接增加硬件資源。當然，API金鑰和頻率限制的管理也是很重要的，可以參考 [DeepSeek API Key與限額](/posts/deepseek-api-key-and-limits/) 這篇文章。

## 常見問題

**Q1：模型跑得慢吞吞的，有啥辦法提速不？**

**A1：**首先查一下你的顯示卡VRAM夠不夠用。如果模型太大導致頻繁的內存交換，速度肯定會卡。你可以試著加載小一點的模型版本，或者直接升級顯示卡。另外，記得確保顯示卡驅動是最新版，並且 Ollama 容器正確配置了 GPU 資源哦。

**Q2：DeepSeek 模型或 Ollama 框架怎麼更新？**

**A2：**更新 Ollama 框架很簡單，重新運行官方的安裝腳本就行。更新 DeepSeek 模型則是在每個用戶的容器裡執行 `ollama pull <model_name>:<new_version>`。因為每個用戶數據是隔離的，你可以分別給每個用戶更新模型，不會影響其他人。

**Q3：數據私隱還能怎麼加強？**

**A3：**除了本地部署和用戶隔離，你還可以給伺服器設嚴格的防火牆規則，只允許內部網絡訪問。數據傳輸方面，Nginx 可以配置 SSL/TLS 加密（啟用 HTTPS），保證內部網絡通訊安全。同時，定期備份用戶的模型數據和設定，也是保障數據安全不可或缺的環節。
