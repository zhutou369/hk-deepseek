## 例子 1-3：角色設定與任務拆解

**例 1：角色設定唔好太抽象。** 與其寫「你係專家」，不如寫「你係有 5 年經驗嘅香港中小企會計文員，熟悉香港稅務條例」。我測試時發現，加入地區同具體年資，答案會貼地好多。

**例 2：用「步驟」引導思考。** 例如：「請先列出 3 個可能原因，再逐一解釋，最後總結建議。」呢個寫法喺 [DeepSeek 提示詞基礎](/posts/deepseek-prompt-basics/) 都有提過，但實測真係 work。

**例 3：設定輸出長度。** 直接寫「用 150 字內回答」或者「分 3 點，每點不多於 50 字」，比「簡短回答」有效。

## 例子 4-6：上下文與範例約束

**例 4：提供範例（few-shot）。** 想 AI 跟你格式，就俾一兩個例子。例如：「以下係兩個正確格式：1. 產品：價格 2. 產品：價格。請跟住呢個格式輸出。」

**例 5：限定知識範圍。** 寫「只根據以下文字回答，唔好自己加資料」，可以減少幻覺。如果你用 RAG，呢句幾乎係必須。

**例 6：處理唔確定嘅情況。** 加一句「如果資料不足，請回答『唔確定』，唔好猜測」。我試過冇加呢句，AI 會自己作數據。

## 例子 7-10：輸出格式與常見錯誤

**例 7：用 JSON 約束。** 寫「請用 JSON 格式輸出，key 必須係 name、price、stock」。如果要接自動化工作流，呢步好關鍵。

**例 8：表格輸出。** 寫「用 Markdown 表格，欄位：項目、數量、備註」。

**例 9：避免「廢話開頭」。** 加「直接回答，唔好講『好的』或者『當然可以』」。

**例 10：分段處理長任務。** 寫「第一步：總結；第二步：列出 3 個建議；第三步：用 50 字總結」。呢個技巧喺 [DeepSeek API 重試指南](/posts/deepseek-api-retry-guide/) 都有類似思路，因為分段可以減少 timeout。

## 常見問題

**Q1：提示詞係咪越長越好？**
唔係。我測試時發現，超過 500 字嘅提示詞，如果冇結構，效果反而差。建議用「角色 + 任務 + 格式 + 限制」四段式。

**Q2：點解 AI 唔跟我指定嘅格式？**
好多時係因為你冇明確講「必須」。試下加「必須嚴格按照以下格式，唔可以加其他文字」。

**Q3：用 API 定網頁版好？**
如果只係試提示詞，網頁版最快。如果要自動化，就要用 API，記得睇 [API key 與限額說明](/posts/deepseek-api-key-and-limits/)。

**Q4：提示詞入面可唔可以包含中文？**
可以，DeepSeek 對中文支援好好。但如果你要輸出 JSON，建議 key 用英文，避免編碼問題。

**Q5：有冇話邊個模型版本最好？**
以官方文檔為準。我今次用 V3（2025-03-24），一般任務夠用；如果要更長上下文，可以睇官方定價頁。

## 操作步驟（3 步完成第一個提示詞）

1. 打開 [chat.deepseek.com](https://chat.deepseek.com)，登入後選擇「新對話」。
2. 輸入以下提示詞（可直接複製）：「你係香港中小企市場推廣主任，請用 3 點列出提升 Instagram 互動率嘅方法，每點不多於 40 字，用 Markdown 列表輸出。」
3. 如果輸出太長，回覆「請縮短到 100 字內」，觀察分別。

如果你想喺本地跑 model，可以參考 [Ollama 本地設定教學](/posts/deepseek-ollama-local-setup/)，設定好之後再用同樣提示詞測試，會發現速度同穩定度有唔同。

最後提提你：提示詞係要不斷試，唔好期望一次就完美。我通常會開一個 text file 記低邊個寫法最 work，慢慢就累積到自己嘅模板庫。
