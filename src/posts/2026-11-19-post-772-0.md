## 为什么要选长文本工具

香港中小企很常见的场景：一份几十页的合约、一份 audit report、一堆客户会议记录。你不会想逐页看，但又不敢完全信 AI。关键不是“哪个模型最强”，而是“哪个帮你省最多时间，同时你控得住风险”。

我测试时发现，三个工具都支持直接上传 PDF 或贴长文，但处理方式和提示词要求有明显区别。下面用三个维度打分（1-5 分，5 分最好），纯粹我个人主观体验。

## 三个维度实测对比

**维度一：长文吸附力（上传后会不会漏内容）**

- DeepSeek：4 分。80 页 PDF 上传后，我问“第 37 页的应收账款数字”，它答得出，但偶尔要追问一次才准。以官方文档为准，它网页版有字数上限，很长的文件建议分段。
- Kimi：4.5 分。它本来就主打长文本，吸附力比较稳，我问跨页的关联问题，它能自己找前文。
- 豆包：3.5 分。一般摘要没问题，但太长的文件，它有时会“浓缩”掉细节，得明确叫它“不要省略”。

**维度二：追问灵活度（来回对话）**

- DeepSeek：4.5 分。追问时逻辑连贯，你叫它“用表格列出”，它真出表。我试过让它比较两份合约的差异条款，它逐条对，不会乱编。
- Kimi：4 分。追问也顺，但如果你问得太发散，它会拉回摘要，要你重新聚焦。
- 豆包：4 分。反应快，语气像客服，适合不想琢磨 prompt 的用户。

**维度三：数据安全和部署弹性**

- DeepSeek：4.5 分。重点是它有开源模型，你可以用 Ollama 在自己机器或公司 server 跑，不用把敏感文件上传。这点对香港中小企很重要。想知怎么装，可以看我之前写的[本地 Ollama 部署教学](/posts/deepseek-ollama-local-setup/)。
- Kimi：3 分。主要是云端，企业版有得谈，但个人用户没有本地选项。
- 豆包：3 分。同样以云端为主，合规设定要问回官方。

## 三步实操：怎么上传和追问

以下步骤以 DeepSeek 网页版为例，其他两个工具大同小异。

**第一步：开新对话，先上传再问**

不要一上来就贴问题。先上传 PDF 或贴上全文，等它确认收到，再下指令。比如：“以下是一份 80 页年报，请先确认你收到，不要摘要。”这样能减少它漏读。

**第二步：用结构化指令抽数**

别问“这份文件讲什么”，要问：“请用表格列出第 3 页至第 5 页的收入、成本、毛利率，不确定的格写‘未提供’。”我测试时发现，越具体的格式要求，出错率越低。想学 prompt 基本功，可以参考[提示词入门](/posts/deepseek-prompt-basics/)。

**第三步：分段追问，不要一次问十样**

长文本场景最忌一次问十条问题。我通常分三轮：第一轮抽事实，第二轮做比较，第三轮让它用一段话总结。如果遇到 API 报错或 timeout，可以看[重试指南](/posts/deepseek-api-retry-guide/)。

## 常见问题

**Q1：三个工具哪个支持最长的文件？**

以官方公开信息为准，Kimi 在长文本宣传上最进取，DeepSeek 和豆包都有字数上限。实际上限会随版本更新，建议上传前看回官网说明。

**Q2：可以完全免费用吗？**

三个都有免费额度或免费网页版，但高频使用或 API 调用通常要收费。DeepSeek API 的价格和限制，可以看[API Key 与额度说明](/posts/deepseek-api-key-and-limits/)。

**Q3：敏感文件上传安全吗？**

如果你处理客户资料或合约，最稳的是用本地开源模型。DeepSeek 的开源权重可以在 Ollama 跑，数据不出自己机器。

**Q4：哪个最适合写会议记录？**

我实测觉得豆包最快出稿，Kimi 最齐全，DeepSeek 最适合你之后要再加工或抽数据。

**Q5：为什么有时上传完它说读不到？**

可能是 PDF 扫描档（图片）而不是文字层。你可以先在电脑用 OCR 转成文字，再贴上。如果是网页登录问题，可以看[登录排错](/posts/deepseek-web-login-troubleshoot/)。

## 我的选型建议

如果你个人用户想快：豆包。如果你经常读超长文件：Kimi。如果你要抽数据、做分析，或者公司有数据安全要求：DeepSeek，尤其是配合本地部署。

我上周升级后的做法是：日常问答用 DeepSeek 网页版，敏感文件用 Ollama 跑本地模型，两边互补。记住，任何工具出的数字，尤其是财务和法律内容，都要人手复核一次。
