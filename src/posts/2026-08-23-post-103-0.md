## 點解要用 DeepSeek 搞情報監聽？

以前想做精準情報分析，要嘛砸錢請一堆人，要嘛搞好複雜的機器學習模型。但 DeepSeek 一出，這事兒就簡單多了。它的語言理解和生成能力，能輕輕鬆鬆處理各種非結構化數據，像新聞稿、社交帖文、論壇討論這些。你想像一下，比如有個關於新技術（像量子電腦）的討論，或競爭對手偷偷發佈了新產品，單靠關鍵字可能就錯過關鍵細節了。DeepSeek 能幫我們深挖內容，甚至總結出趨勢、風險或商機，比老一套方法強多了。而且它的 API 用起來超方便，跟 Node.js 這些新潮框架搭檔簡直絕配。

## 系統核心概念與技術棧

這套分佈式情報監聽系統，主要分幾個部分：

1.  **數據採集模組 (Crawler/Listener)**：負責從指定網站、API 或 RSS Feed 採集原始數據。我們會用 Node.js 寫簡單的爬蟲。
2.  **消息佇列 (Message Queue, e.g., RabbitMQ)**：分佈式系統的核心，用來緩衝、協調各個模組之間的數據流，確保數據處理的穩定性和擴展性。
3.  **DeepSeek 分析模組**：接收原始數據，調用 DeepSeek API 進行內容理解、摘要、情感分析、實體提取等。這可是系統的「大腦」。
4.  **數據存儲 (Database, e.g., MongoDB/PostgreSQL)**：將分析過的結構化情報存儲起來，方便後續查詢和報表生成。
5.  **通知與行動模組**：基於特定規則，自動發送通知（Email/SMS/Slack）或者觸發其他自動化流程。

至於技術選型，我主要推薦用 **Node.js 20.x.x**。它異步、事件驅動的特點，特別適合搞網絡爬蟲和 API 服務這些 IO 密集型任務。當然啦，DeepSeek 那個超厲害的語言模型 API，絕對是這套系統的大腦和核心。

## 開波：分佈式情報監聽系統三步走

### 第一步：基礎環境設置與數據採集模組

首先，確保你的開發環境裝好了 Node.js (推薦用 `Node.js 20.x.x` 或更新的版本) 和 npm。接著，我們需要 DeepSeek API Key。還沒有？直接去 [DeepSeek 官網](https://platform.deepseek.com/) 申請就行。關於 DeepSeek API Key 和用量限制，你可以看看我們之前寫過的攻略：[DeepSeek API Key 同用量指南](/posts/deepseek-api-key-and-limits/)。

開一個新的 Node.js 專案：

```bash
mkdir intelligence-monitor
cd intelligence-monitor
npm init -y
npm install express axios cheerio amqplib dotenv
```

`express` 用來起簡單的 API 服務（非必需，但方便測試），`axios` 用來發 HTTP 請求，`cheerio` 用來解析 HTML，`amqplib` 是 RabbitMQ 客戶端，`dotenv` 用來管理環境變數。

數據採集模組的核心就是爬蟲。例如，我們可以寫一個簡單的服務去監聽某個科技新聞網站：

```javascript
// scraper.js (簡化版)
const axios = require('axios');
const cheerio = require('cheerio');
const amqp = require('amqplib');

async function scrapeTechNews() {
    try {
        const response = await axios.get('https://example.com/tech-news'); // 替換為實際目標網站
        const $ = cheerio.load(response.data);
        const articles = [];

        $('article.news-item').each((i, el) => {
            const title = $(el).find('h2 a').text();
            const link = $(el).find('h2 a').attr('href');
            const summary = $(el).find('p.summary').text();
            articles.push({ title, link, summary });
        });

        const connection = await amqp.connect('amqp://localhost');
        const channel = await connection.createChannel();
        const queue = 'raw_intelligence_data';
        await channel.assertQueue(queue, { durable: true });

        for (const article of articles) {
            channel.sendToQueue(queue, Buffer.from(JSON.stringify(article)), { persistent: true });
            console.log(`[x] Sent article to queue: ${article.title}`);
        }

        setTimeout(() => {
            connection.close();
        }, 500);

    } catch (error) {
        console.error('Scraping error:', error.message);
    }
}

// 每隔一段時間運行一次
setInterval(scrapeTechNews, 3600000); // 每小時運行一次
scrapeTechNews(); // 啟動時立即運行一次
```

記得要啟動一個 RabbitMQ 服務，例如用 Docker：`docker run -d --hostname my-rabbit --name some-rabbit -p 5672:5672 -p 15672:15672 rabbitmq:3-management`。

### 第二步：DeepSeek 智能分析與 RAG 優化

原始數據進了 RabbitMQ 隊列之後，我們就要搞另一個 Node.js 服務來處理這些數據，然後調用 DeepSeek API 進行分析。想讓分析結果更準確，特別是針對某些專業領域的情報，我們可以試試 RAG (Retrieval Augmented Generation) 架構。說白了，就是讓 DeepSeek 在回答前，先去你的私有或外部知識庫裡找找相關資料，再結合這些資料生成更精準、更符合語境的回應。你甚至可以考慮用 Ollama 在本地搭一個輕量級模型，充當 RAG 的檢索部分：[DeepSeek x Ollama：本地部署 LLM 實戰教學](/posts/deepseek-ollama-local-setup/)。

![DeepSeek 香港企業應用架構演示](/static/images/photo-1522071820081-009f0129c71c.jpg)

以下是一個簡化版的 DeepSeek 分析模組範例：

```javascript
// deepseek-analyzer.js
require('dotenv').config();
const amqp = require('amqplib');
const axios = require('axios');

const DEEPSEEK_API_KEY = process.env.DEEPSEEK_API_KEY;
const DEEPSEEK_API_URL = 'https://api.deepseek.com/chat/completions';

async function analyzeWithDeepSeek(article) {
    const prompt = `請用香港繁體中文簡潔地分析以下科技情報，並提取出其核心技術、潛在影響同重要性：

標題: ${article.title}
摘要: ${article.summary}

分析結果（例如：核心技術：XXX，影響：YYY，重要性：ZZZ）：`;

    try {
        const response = await axios.post(DEEPSEEK_API_URL, {
            model: 'deepseek-chat',
            messages: [{
                role: 'user',
                content: prompt
            }],
            temperature: 0.7,
            max_tokens: 500
        }, {
            headers: {
                'Authorization': `Bearer ${DEEPSEEK_API_KEY}`,
                'Content-Type': 'application/json'
            },
            // 在發送請求時，考慮加入重試機制
        });
        return response.data.choices[0].message.content;
    } catch (error) {
        console.error('DeepSeek API error:', error.response ? error.response.data : error.message);
        // 處理 API 錯誤，例如重試
        // 更多關於 DeepSeek API 重試嘅策略，可以睇我哋嘅教學：[DeepSeek API 重試策略指南](/posts/deepseek-api-retry-guide/)
        return '分析失敗。';
    }
}

async function consumeAndAnalyze() {
    const connection = await amqp.connect('amqp://localhost');
    const channel = await connection.createChannel();
    const queue = 'raw_intelligence_data';
    const processedQueue = 'analyzed_intelligence_data';

    await channel.assertQueue(queue, { durable: true });
    await channel.assertQueue(processedQueue, { durable: true });

    console.log("[*] Waiting for messages in %s. To exit press CTRL+C", queue);

    channel.consume(queue, async (msg) => {
        if (msg !== null) {
            const article = JSON.parse(msg.content.toString());
            console.log(`[x] Received raw article: ${article.title}`);

            const analysis = await analyzeWithDeepSeek(article);
            const fullAnalysis = { ...article, deepseek_analysis: analysis };

            channel.sendToQueue(processedQueue, Buffer.from(JSON.stringify(fullAnalysis)), { persistent: true });
            console.log(`[x] Sent analyzed article: ${article.title}`);

            channel.ack(msg);
        }
    }, { noAck: false });
}

consumeAndAnalyze();
```

一個寫得好、表達清晰的 Prompt 對分析結果超級重要！不懂怎麼寫？可以參考我們這篇：[DeepSeek Prompt 基礎教學](/posts/deepseek-prompt-basics/)。

### 第三步：結果處理與自動化閉環

DeepSeek 分析完畢的數據，也就是那些處理好的情報，會進入 `analyzed_intelligence_data` 隊列。這是整個系統自動化流程的收尾環節，我們可以再建個服務來處理這個隊列，把情報存進數據庫，然後根據你設定的規則自動發送通知或觸發其他操作。

![網絡情報監測系統Node.js架構圖](/static/images/photo-1516321318423-f06f85e504b3.jpg)

```javascript
// processor.js
const amqp = require('amqplib');
const { MongoClient } = require('mongodb'); // 用 MongoDB 舉例
const nodemailer = require('nodemailer'); // 用嚟發郵件通知

const MONGODB_URI = process.env.MONGODB_URI || 'mongodb://localhost:27017';
const DB_NAME = 'intelligenceDB';
const COLLECTION_NAME = 'tech_intelligence';

// 設定郵件發送器
const transporter = nodemailer.createTransport({
    service: 'gmail', // 或其他SMTP服務
    auth: {
        user: process.env.EMAIL_USER,
        pass: process.env.EMAIL_PASS
    }
});

async function processAnalyzedData() {
    const client = new MongoClient(MONGODB_URI);
    try {
        await client.connect();
        console.log('Connected to MongoDB');
        const db = client.db(DB_NAME);
        const collection = db.collection(COLLECTION_NAME);

        const connection = await amqp.connect('amqp://localhost');
        const channel = await connection.createChannel();
        const processedQueue = 'analyzed_intelligence_data';

        await channel.assertQueue(processedQueue, { durable: true });
        console.log("[*] Waiting for analyzed messages. To exit press CTRL+C", processedQueue);

        channel.consume(processedQueue, async (msg) => {
            if (msg !== null) {
                const intelligence = JSON.parse(msg.content.toString());
                console.log(`[x] Received analyzed intelligence: ${intelligence.title}`);

                // 存儲到數據庫
                await collection.insertOne(intelligence);
                console.log(`[x] Saved to DB: ${intelligence.title}`);

                // 根據規則發送通知 (例如：如果 DeepSeek 分析結果提到「突破性」或「關鍵技術」)
                if (intelligence.deepseek_analysis && intelligence.deepseek_analysis.includes('突破性')) {
                    const mailOptions = {
                        from: process.env.EMAIL_USER,
                        to: 'your_email@example.com', // 替換為實際收件人
                        subject: `【重要】新科技情報：${intelligence.title}`,
                        text: `DeepSeek 分析：\n${intelligence.deepseek_analysis}\n\n原文連結：${intelligence.link}`
                    };
                    await transporter.sendMail(mailOptions);
                    console.log('Email notification sent!');
                }

                channel.ack(msg);
            }
        }, { noAck: false });

    } catch (error) {
        console.error('Data processing error:', error.message);
    }
}

processAnalyzedData();
```

### 常見問題

**Q1: 點解 DeepSeek 的回應有時不夠準確？**

DeepSeek 的表現嘛，很大程度取決於你給它的 Prompt 怎麼樣。如果回應不夠精準，你可以試試以下方法：
*   **優化 Prompt**：提供更清晰、具體的指令，或者加入範例（Few-shot prompting）。
*   **增加上下文**：利用 RAG 架構，提供 DeepSeek 額外的背景資訊或本地知識庫內容。
*   **調整參數**：將 `temperature` 降低到 0.1-0.3 之間，可以讓模型輸出更集中、更可預測，減少發散性回應。

**Q2: 怎樣處理大量數據請求時的 API 限制？**

當系統需要處理大量數據並頻繁調用 DeepSeek API 時，可能會遇到速率限制（Rate Limit）。我們有幾種方法可以處理：
*   **重試機制**：當 API 請求失敗時，別急著放棄，可以試試帶有指數退避（Exponential Backoff）的重試機制。這方面我們有專門的文章教你：[DeepSeek API 重試策略指南](/posts/deepseek-api-retry-guide/)。
*   **佇列緩衝**：利用像 RabbitMQ 這類消息佇列，將 API 請求放入佇列，然後以一個受控的速度從佇列中取出並發送。
*   **並行限制**：限制同時發送的 API 請求數量，避免瞬間產生過多請求。

**Q3: 系統擴展性怎樣考慮？**

Node.js 搭配消息隊列的架構，本身就特別能打，擴展性槓槓的：
*   **增加分析節點**：當數據量大時，可以部署多個 `deepseek-analyzer.js` 實例，它們會自動從 RabbitMQ 的同一個佇列中消費消息，輕鬆實現水平擴展。
*   **獨立服務**：將採集、分析、存儲和通知各個模組拆分成獨立的小服務，各自獨立部署和擴展。
*   **負載均衡**：在採集模組和外部資源之間，或者在多個 DeepSeek 分析節點之間，可以使用負載均衡器來分發請求。
