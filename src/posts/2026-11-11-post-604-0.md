## 我點樣開始測 DeepSeek 翻譯

上個月 15 號，我喺 [DeepSeek 官方平台](https://platform.deepseek.com) 用 API 版本 `deepseek-chat`（模型標示 `DeepSeek-V3`）做咗一輪中英翻譯實測。測試材料係三份香港中小企常用文件：一份採購合同、一份產品說明書、一份客服電郵範本。我嘅目標好簡單：睇下佢輸出嘅繁體中文夠唔夠「港味」，同埋專業術語會唔會亂譯。

結果係：默認設定下，英文譯中文嘅語感偏向書面普通話，例如「please be advised」會譯成「請注意」，而唔係香港慣用嘅「請留意」。專業術語方面，「indemnity clause」譯成「賠償條款」冇錯，但「force majeure」竟然譯成「不可抗力因素」——多咗個「因素」，法律文件就唔夠乾淨。

呢啲問題唔係模型唔得，而係提示詞未到位。以下我分享三個實際操作步驟，你可以直接用喺 [DeepSeek 網頁版](https://chat.deepseek.com) 或者 API 度。

## 三個步驟執靚翻譯輸出

### 步驟一：用系統提示詞鎖定「香港繁體中文」語域

唔好淨係打「翻譯成繁體中文」。我測試時發現，要明確講「香港繁體中文（zh-HK）」，再加一句「避免使用中國內地公文用語」。例如：

```
你係香港專業翻譯員。請將以下英文翻譯成香港繁體中文（zh-HK），用詞要貼近香港報刊同商業文件慣例。唔好加入「因素」「進行」「予以」等內地慣用虛詞。
```

呢句提示詞可以放喺對話開頭，或者 API 嘅 `system` role。如果你用 API，可以參考 [DeepSeek 提示詞基礎教學](/posts/deepseek-prompt-basics/) 調整參數。

### 步驟二：預先餵術語表，唔好靠模型估

專業文件一定要自備術語對照。我將 20 個常見法律同財務術語整成一個 JSON 清單，喺提示詞入面直接寫明「以下術語必須跟指定譯法」。例如：

```json
{
  "force majeure": "不可抗力",
  "indemnity": "彌償",
  "warranty": "保證條款",
  "confidential information": "保密資料"
}
```

咁做之後，「indemnity」就唔會譯成「賠償」而係「彌償」，符合香港法律文件慣例。記住，術語表要每次對話都附上，因為模型唔會自動記住。

### 步驟三：分段翻譯，再人手潤色語感

一次過丟成篇文件入去，模型容易前後用詞唔一致。我嘅做法係按段落切開，每段 200 字以內，逐段翻譯。翻譯完之後，我會用一個「潤色提示」叫模型自己檢查：

```
請檢查以下譯文有冇普通話語法殘留，例如「的」字過多、被動句氾濫。如果有，請改成香港慣用句式。
```

呢步好使好用，尤其係客服電郵呢類要自然語感嘅文本。如果你想自動化呢個流程，可以睇下 [DeepSeek API 重試機制指南](/posts/deepseek-api-retry-guide/)，避免逐段呼叫時遇到 rate limit。

## 常見問題

**問：DeepSeek 翻譯繁體中文會唔會出簡體字？**
答：默認情況下，如果你只寫「繁體中文」，偶爾會混入簡體字。明確寫「zh-HK」同埋要求「全部輸出必須係繁體字」可以大幅減少。以官方文檔為準，模型本身支援多語言輸出，但唔保證 100% 純繁體，建議翻譯後用轉換工具檢查一次。

**問：API 翻譯收費點計？**
答：根據官方公開資訊，`deepseek-chat` 模型按 token 計費，輸入同輸出價格不同。具體金額請以 [platform.deepseek.com](https://platform.deepseek.com) 嘅定價頁為準，我測試時嘅價格已經可能變咗。

**問：可唔可以本地跑 DeepSeek 做翻譯？**
答：可以，用 Ollama 就得。不過本地模型版本同量化程度會影響翻譯質素，詳情可以參考 [DeepSeek Ollama 本地安裝教學](/posts/deepseek-ollama-local-setup/)。我試過 7B 量化版，語感明顯不及 API 版本，但勝在免費同私隱好。

**問：點解翻譯出嚟嘅句子好長？**
答：英文本身鍾意用從句，模型直譯就會跟住長。你可以在提示詞加一句「每句唔好超過 25 個中文字，長句請拆開」。我實測有效，尤其係說明書類文本。

**問：有冇辦法保留原文格式，例如 bullet point？**
答：有。提示詞寫明「請保留原本嘅 Markdown 格式同項目符號」，然後將原文用 code block 包住。如果格式好複雜，建議先轉做純文字再翻譯，減少模型出錯。
