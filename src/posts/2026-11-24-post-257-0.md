## 先講結論：三個最常見的觸發點

上週把 DeepSeek 客戶端升到 2025.02 版，我連續碰到三次「生成到一半卡住」、一次「直接報錯」。排查一輪，問題基本都落在三個地方：溫度設太高、`max_tokens` 設太小、提示詞裡夾了容易觸發過濾的字眼。這篇不扯理論，直接給一份能照著動手的排查清單。

## 第一步：檢查溫度參數是否過高

溫度（temperature）管的是輸出的隨機性。拿我測的 2025.02 版來說，`temperature` 一旦拉到 1.2 以上，模型在長文本任務裡就更容易重複、跳躍，甚至中途停住。這不是 bug，是高隨機性讓模型「不知道怎麼接下去」。

操作上，把溫度調回 0.7 到 0.9 之間再試。用 API 就直接改請求參數；用網頁版就在設定裡找「創造力」或「溫度」滑桿。跑本地模型的話，比如用 Ollama 加載，記得看一眼 Modelfile 裡的 `PARAMETER temperature`，別讓它繼承了預設的高值。

我測試時發現，同一個提示詞在 0.8 下穩穩輸出，在 1.3 下大概第三次就斷。所以與其反覆重試，不如先把溫度降下來。

## 第二步：確認輸出長度與上下文限制

第二個常見原因是長度設定。`max_tokens` 設太小，模型會在你覺得「還沒講完」的地方直接收尾；設太大，又可能因為上下文窗口不夠而失敗。以 DeepSeek 公開的 API 文檔為例，不同模型各有上下文上限，具體數字以官方文檔為準。

實操建議：先確認你用的模型名稱對應的上下文長度，再把 `max_tokens` 設成預期輸出長度的 1.5 倍左右。比如你要寫 800 字，就設 1200 到 1500 tokens。用網頁版通常不用手動設，但遇到中斷時可以試著把問題拆成兩段來問。

另外，如果把整篇長文一次丟進去讓模型總結，很容易撞到上下文上限。這時可以參考站內的 [DeepSeek 提示詞基礎](/posts/deepseek-prompt-basics/)，用分段摘要的方式處理。

## 第三步：排查敏感詞與內容過濾

第三個原因比較隱蔽：提示詞或上下文裡包含敏感詞，觸發內容過濾，導致生成中斷或直接報錯。常見觸發場景包括醫療建議、金融投資，以及某些政治或成人詞彙。過濾機制不會每次都給明確提示，有時只是安靜地停住。

排查方法很簡單：把提示詞複製到一個新對話，逐段刪減，找出哪一句引起問題。如果必須處理敏感話題，改用中性描述，或者把問題拆成多個不敏感的小問題。要是你通過 API 调用，可以留意返回的錯誤碼；常見的 400 和 422 都與參數或內容有關，具體含義以官方文檔為準。

站內這篇 [DeepSeek API 重試指南](/posts/deepseek-api-retry-guide/) 對錯誤碼有更細的整理，遇到反覆失敗時可以對照著看。

## 常見問題

**Q1：為什麼網頁版有時生成到一半就停住，刷新也沒用？**

先檢查瀏覽器有沒有擴展干擾，再換一個乾淨的無痕視窗。如果還是不行，可能是該時段伺服器負載較高，稍後再試。若你用本地 Ollama 部署，可以參考 [DeepSeek Ollama 本地部署教學](/posts/deepseek-ollama-local-setup/) 確認服務狀態。

**Q2：溫度調低後輸出變得很死板，怎麼辦？**

可以把溫度維持在 0.8 左右，並在提示詞裡加入「請用自然口語」或「避免重複句式」這類指示。必要時，用兩階段生成：先讓模型列大綱，再讓它擴寫。

**Q3：API 一直回傳 429 錯誤，是敏感詞造成的嗎？**

不是。429 通常代表請求頻率過高或額度不足，和敏感詞無關。先檢查你的用量與速率限制，詳見 [DeepSeek API Key 與額度說明](/posts/deepseek-api-key-and-limits/)。

**Q4：如何快速判斷是中斷還是模型本來就講完了？**

看輸出結尾有沒有句號或完整段落。如果停在半句，通常是中斷；如果結尾完整但內容短，可能是 `max_tokens` 太小。把 `max_tokens` 調大 200 到 300 再試一次即可。

**Q5：敏感詞過濾有沒有官方清單可以查？**

沒有公開的完整清單。實務上只能靠逐段測試，並以官方文檔說明的內容政策為準。遇到不確定的詞，改用同義的中性表達通常能繞過。
