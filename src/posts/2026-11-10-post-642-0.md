## 為什麼要用 DeepSeek 整理會議紀要？

上週升級 DeepSeek 網頁版後，我試著把一段 45 分鐘的廣東話會議逐字稿丟給它整理。結果出乎意料：它不僅能抓出決議事項，還會把「阿John話下星期交」轉成「John 負責下週提交」的正式表述。香港中小企開會，記錄通常靠人手摘錄，耗時又易漏。DeepSeek 的長上下文能力（具體上限以文檔為準）正好解決這個痛點，前提是 Prompt 要寫對。

## 實測 Prompt 模板（2025 年 3 月更新）

我測試時發現，與其叫它「總結會議」，不如給它明確的角色和輸出格式。下面這個模板我調整過三次，適用於 DeepSeek-V3 模型（網頁版或 API 皆可）：

```
你是一位專業的會議記錄員。以下是會議逐字稿，請整理成會議紀要，格式要求：
1. 會議主題、日期、參與者（從逐字稿推斷，不確定則標「待確認」）
2. 討論重點（條列式，每點不超過兩行）
3. 決議事項（明確寫出「誰、做什麼、何時完成」）
4. 待跟進問題（列出未解決事項）
5. 使用繁體中文，語氣正式但簡潔。

逐字稿：
[貼上逐字稿]
```

這個模板的關鍵是「角色設定」和「結構化輸出」。如果你想再深入一點提示詞技巧，站內[DeepSeek 提示詞基礎教學](/posts/deepseek-prompt-basics/)有更多範例可以參考。

## 三步操作流程

**第一步：獲取逐字稿**

先將會議錄音轉成文字。你可以用本地工具（如 Whisper）或線上服務，輸出純文字檔。注意：DeepSeek 網頁版有輸入長度限制，太長的逐字稿建議分段處理，或使用 API 並參考[API 重試機制指南](/posts/deepseek-api-retry-guide/)來避開超時問題。

**第二步：貼上 Prompt 並執行**

打開 DeepSeek 對話界面，貼上上面的模板，替換逐字稿部分。若逐字稿超過模型上下文，可先請它「分段摘要」，再合併。我習慣在 Prompt 末尾加一句：「如果逐字稿有不清楚的地方，直接標註『錄音不清』，不要猜測。」這能減少幻覺。

**第三步：人手校對與微調**

AI 生成的紀要仍需人手檢查，特別是數字、日期和專有名詞。我會把輸出貼回 Word，快速核對決議事項是否齊全。若團隊常用 API，可以考慮用[本地 Ollama 部署](/posts/deepseek-ollama-local-setup/)來處理敏感會議內容，避免資料外傳。

## 常見問題

**Q1：逐字稿太長，DeepSeek 網頁版貼不下怎麼辦？**

可以分段處理：先每 10 分鐘摘要一次，再將摘要合併成最終紀要。或者使用 API，具體 token 上限請查閱文檔。

**Q2：廣東話口語化嚴重，DeepSeek 能準確轉書面語嗎？**

我測試時發現，它對常見粵語詞彙（如「傾掂數」「跟進」）處理不錯，但太地道的俗語可能出錯。建議在 Prompt 中加一句：「請將口語轉為正式書面語，不確定則保留原文並標註。」

**Q3：生成的紀要太長，如何精簡？**

在 Prompt 中加入「每點不超過 30 字」或「只保留決議事項和待跟進問題」。也可以事後叫它「壓縮成 200 字摘要」。

**Q4：需要區分發言者嗎？**

如果逐字稿有標註發言者，可以在 Prompt 中要求「按發言者整理觀點」。若沒有，AI 只能根據上下文推斷，準確度有限。

**Q5：DeepSeek 會保存會議內容嗎？**

根據隱私政策，網頁版對話可能用於模型改進。敏感會議建議使用 API 或本地部署，並參考[API Key 與用量限制說明](/posts/deepseek-api-key-and-limits/)來管理權限。
