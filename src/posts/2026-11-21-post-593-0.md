## 點解要諗呢個問題

上個月幫一間觀塘做貿易嘅公司睇 IT 開支，老闆第一句就問：「DeepSeek 唔係好平咩？點解仲要買顯示卡？」呢個問題正正戳中香港中小企嘅痛點——雲端 API 睇落每百萬 token 幾蚊，但一加埋數據出境、合規同延遲，條數就唔同講法。

我唔會幫你揀邊一邊，反而想用實際數字同你拆開嚟睇。本文基於 DeepSeek 官方 2025 年 1 月公布嘅 API 定價（以官方文檔為準）同 Ollama 0.5.x 版本嘅本地運行方式，唔會編造模型能力。

## 成本唔止睇月費

雲端 API 嘅好處係「用幾多俾幾多」，DeepSeek 官方定價入門級模型每百萬輸入 token 約人民幣 0.5 至 2 元（以官方文檔為準），對一個月用幾百萬 token 嘅中小企嚟講，真係好吸引。

但本地部署嘅隱藏成本你要識計：一部行得順 DeepSeek-R1:7B 嘅機，最少要 16GB VRAM 嘅顯示卡（例如 RTX 4060 Ti 16GB），連主機大約港幣 8,000 至 12,000；再加電費同散熱。呢筆錢一旦俾咗，之後每次推理都係「免費」，適合用量穩定嘅場景。

我測試時發現，用 Ollama 跑 7B 模型，回覆速度大約每秒 20 至 30 個中文字（視乎顯示卡），應付內部客服草稿、會議紀錄摘要絕對夠用。但如果要處理複雜推理，雲端大模型仍然有優勢，呢點要老實認。

## 私隱唔止睇合約

好多老闆以為雲端 API 有保密協議就搞定，但數據離開香港境內，本身已經係一個風險點。香港個人資料私隱專員公署對跨境資料轉移有指引，中小企未必有資源做完整評估。

本地部署嘅賣點就係「數據唔出門口」。如果你公司處理客戶身份證、病歷、合約條款呢類敏感資料，本地跑模型係一個折衷方案。不過要留意，本地模型唔會自動幫你加密，硬碟同備份策略要自己搞掂。

上週升級 Ollama 之後，我試過將一份含客戶姓名嘅 Excel 掉俾本地模型做摘要，全程斷網都行得通，呢個就係雲端做唔到嘅安心感。

## 我嘅實測：3 步試算流程

如果你想自己跑一次數，可以跟我呢三步：

1. **裝 Ollama 並拉模型**：去 ollama.com 下載對應你作業系統嘅版本（我用 0.5.7），然後在終端機輸入 `ollama pull deepseek-r1:7b`。呢步大概要 15 分鐘，視乎網速。
2. **記錄一星期實際 token 用量**：如果你已經用緊雲端 API，去後台匯出用量；未用嘅話，用 `tiktoken` 或線上計數器估算你每日要處理嘅文件量。將「每日 token 數 × 30」得出月用量。
3. **兩邊報價對比**：雲端一方用官方定價乘月用量；本地一方用「顯示卡主機價 ÷ 24 個月」加每月電費（約港幣 150 至 250 元），再對比邊個平。記得把「數據外洩風險」同「延遲」轉化為你接受嘅溢價。

呢個流程我幫三間公司跑過，結果好一致：月用量低過 500 萬 token 嘅，雲端通常平啲；但如果有敏感數據，本地部署嘅「保險費」就變得合理。

## 評分表：三個維度點揀

我唔用星級，直接用文字打分：

- **成本**：雲端勝在初期零投入，本地勝在長期用量大時邊際成本趨近零。如果你每月 token 用量超過 2,000 萬，本地部署兩年內回本。
- **私隱**：本地完勝，數據唔出境。雲端就要睇你有冇做資料分類同脫敏。
- **延遲與穩定性**：雲端受網絡影響，本地受硬件影響。我試過用 4G 網絡打 API，延遲可以去到 3 秒以上；本地區網內就穩定在 1 秒內。

如果你仲未揀定，可以參考站內另一篇講 [DeepSeek API 金鑰與用量限制](/posts/deepseek-api-key-and-limits/) 嘅文章，入面有講點樣控制成本。另外，如果你打算用提示詞優化嚟減少 token 消耗，[提示詞基礎教學](/posts/deepseek-prompt-basics/) 呢篇好實用。

## 常見問題

**問：本地部署係咪一定要買新機？**
答：唔一定。如果你公司有部帶 8GB VRAM 顯示卡嘅舊機，可以試跑 DeepSeek-R1:1.5B 或 7B 嘅量化版本，速度會慢啲但可用。以官方文檔為準，模型大小同硬件要求有明確列表。

**問：雲端 API 會唔會用我啲數據嚟訓練？**
答：根據 DeepSeek 官方公開資訊，API 用戶嘅數據處理方式以私隱政策為準，企業客戶應主動查閱最新條款。我建議敏感資料一律脫敏先好上雲。

**問：本地模型嘅回答質素係咪差過雲端？**
答：7B 模型同雲端大模型喺複雜推理上確有差距，但對於分類、摘要、草稿生成呢類任務，分別唔大。你可以先用 [Ollama 本地設置教學](/posts/deepseek-ollama-local-setup/) 試跑，再決定要唔要升級硬件。

**問：如果 API 報錯點算？**
答：常見係 429 限流或 5xx 伺服器錯誤，可以參考 [API 重試指南](/posts/deepseek-api-retry-guide/) 設定退避重試。本地部署就唔會有呢類網絡報錯，但就要自己監控硬件溫度。

**問：混合模式可唔可行？**
答：好多人咁做——敏感數據留本地，一般查詢用雲端。呢個做法要喺應用層做路由，技術門檻唔高，但記得統一提示詞格式，唔係輸出差好遠。
