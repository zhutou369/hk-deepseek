## 什麼是流式響應與打字機效果？

簡單說，流式響應就是 API 不會等所有數據都生成完才給你，而是會「一片一片」地陸續傳過來。像 DeepSeek 這種大模型，生成完整答案需要點時間，流式傳輸能讓用戶更快看到部分內容，不用傻等。

「打字機效果」嘛，就是前端收到數據片段後，不一下子全顯示，而是像打字一樣，一個字一個字慢慢蹦出來。這樣超像真人對話，用戶體驗瞬間飆升！截至2024年第一季，DeepSeek API 的流式傳輸功能已經超穩了，搞定這效果妥妥的。

## 第一步：後端 API 串流服務建置

後端這步，就是幫前端轉發請求給 DeepSeek API，然後把收到的流式響應再傳回前端。這裡我們拿 Node.js 和 `express` 來簡單演示下：

```javascript
// server.js (Node.js + Express 示例)
const express = require('express');
const fetch = require('node-fetch'); // 或其他 HTTP Client 庫
const app = express();
const port = 3000;

app.use(express.json());
app.use((req, res, next) => {
    res.setHeader('Access-Control-Allow-Origin', '*'); // 允許跨域請求
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, OPTIONS');
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization');
    next();
});

app.post('/stream-chat', async (req, res) => {
    res.setHeader('Content-Type', 'text/event-stream');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('Connection', 'keep-alive');

    const { messages } = req.body;
    try {
        const deepseekResponse = await fetch('https://api.deepseek.com/chat/completions', {
            method: 'POST',
            headers: {
                'Content-Type': 'application/json',
                'Authorization': `Bearer YOUR_DEEPSEEK_API_KEY` // 替換為你嘅 API Key
            },
            body: JSON.stringify({
                model: "deepseek-chat", // 或者你選擇嘅模型
                messages: messages,
                stream: true // 關鍵設定：開啟流式輸出
            })
        });

        if (!deepseekResponse.ok) {
            const errorText = await deepseekResponse.text();
            console.error('DeepSeek API 錯誤:', deepseekResponse.status, errorText);
            return res.status(deepseekResponse.status).send(`DeepSeek API 錯誤: ${errorText}`);
        }

        const reader = deepseekResponse.body.getReader();
        const decoder = new TextDecoder('utf-8');

        while (true) {
            const { done, value } = await reader.read();
            if (done) {
                console.log('DeepSeek Stream Complete');
                break;
            }
            const chunk = decoder.decode(value, { stream: true });
            // DeepSeek API 的 stream 響應是 SSE (Server-Sent Events) 格式
            // 每個 chunk 可能包含多個 event 或不完整的 event
            const lines = chunk.split('\n').filter(line => line.trim() !== '');
            for (const line of lines) {
                if (line.startsWith('data: ')) {
                    const data = line.substring(6);
                    if (data === '[DONE]') {
                        res.write('data: [DONE]\n\n'); // 轉發結束標記
                        res.end();
                        return;
                    }
                    try {
                        const json = JSON.parse(data);
                        // 提取你需要的部分，例如 content
                        const content = json.choices[0].delta.content || '';
                        if (content) {
                            res.write(`data: ${JSON.stringify({ content })}\n\n`); // 將內容轉發給前端
                        }
                    } catch (e) {
                        console.error('JSON Parsing Error:', e, 'Raw data:', data);
                    }
                }
            }
        }
    } catch (error) {
        console.error('服務器內部錯誤:', error);
        res.status(500).send('服務器內部錯誤');
    }
});

app.listen(port, () => {
    console.log(`後端服務器運行在 http://localhost:${port}`);
});
```
這段 Node.js 代碼，大家可以看到怎麼從 DeepSeek API 收到 SSE 數據，然後只挑有用的內容，再以同樣的 SSE 格式發給前端。記得把 `YOUR_DEEPSEEK_API_KEY` 換成你自己的 Key 哦！這種架構能大大保證 API Key 的安全，還能搞定跨域問題。

## 第二步：前端接收並處理流式數據

前端這裡要用到 `fetch` API 和 `ReadableStream` 來接收後端傳來的流式數據。因為後端已經把 DeepSeek 的複雜響應處理過了，前端就只管解析 `data: {"content": "..."}\n\n` 這種簡單格式就行了。

```javascript
// index.html (前端 JavaScript 示例)
document.getElementById('sendBtn').addEventListener('click', async () => {
    const input = document.getElementById('userInput');
    const chatOutput = document.getElementById('chatOutput');
    const message = input.value;
    input.value = ''; // 清空輸入框

    // 顯示用戶發送嘅消息
    chatOutput.innerHTML += `<div class="user-message">你: ${message}</div>`;
    
    // 為 AI 回覆準備一個新區域
    const aiResponseDiv = document.createElement('div');
    aiResponseDiv.className = 'ai-message';
    aiResponseDiv.innerHTML = 'AI: <span id="current-ai-response"></span>';
    chatOutput.appendChild(aiResponseDiv);
    const currentAiResponseSpan = aiResponseDiv.querySelector('#current-ai-response');

    try {
        const response = await fetch('http://localhost:3000/stream-chat', { // 後端服務器地址
            method: 'POST',
            headers: {
                'Content-Type': 'application/json'
            },
            body: JSON.stringify({
                messages: [{ role: "user", content: message }]
            })
        });

        if (!response.ok) {
            const errorText = await response.text();
            throw new Error(`HTTP 錯誤: ${response.status} - ${errorText}`);
        }

        const reader = response.body.getReader();
        const decoder = new TextDecoder('utf-8');
        let buffer = '';

        while (true) {
            const { done, value } = await reader.read();
            if (done) {
                console.log('Frontend Stream Complete');
                currentAiResponseSpan.removeAttribute('id'); // 移除臨時ID
                break;
            }

            buffer += decoder.decode(value, { stream: true });
            // 處理 buffer 中完整嘅 SSE 事件
            let eventEndIndex;
            while ((eventEndIndex = buffer.indexOf('\n\n')) !== -1) {
                const event = buffer.substring(0, eventEndIndex + 2); // 包含 \n\n
                buffer = buffer.substring(eventEndIndex + 2);

                if (event.startsWith('data: ')) {
                    const data = event.substring(6).trim();
                    if (data === '[DONE]') {
                        reader.cancel(); // 結束流
                        break;
                    }
                    try {
                        const json = JSON.parse(data);
                        if (json.content) {
                            // 將內容添加到 span，為打字機效果做準備
                            currentAiResponseSpan.dataset.fullText =
                                (currentAiResponseSpan.dataset.fullText || '') + json.content;
                            // 觸發打字機效果
                            typeWriterEffect(currentAiResponseSpan);
                        }
                    } catch (e) {
                        console.error('前端 JSON 解析錯誤:', e, 'Raw data:', data);
                    }
                }
            }
        }
    } catch (error) {
        console.error('獲取流數據失敗:', error);
        currentAiResponseSpan.textContent = '獲取回覆失敗，請稍後再試。';
        currentAiResponseSpan.removeAttribute('id');
    }
});
```

## 第三步：實作打字機效果

前端收到數據後，不是立馬全顯示出來，而是逐個字元慢慢蹦。我們可以用 JavaScript 的 `setTimeout` 或 `requestAnimationFrame` 來實現。看這個簡單的打字機函數：

```javascript
// typeWriter.js (或直接放在 index.html 的 script 標籤內)
let typeInterval; // 用於清除之前的打字機效果

function typeWriterEffect(element) {
    // 如果之前有正在運行嘅打字機效果，先清除佢
    if (typeInterval) {
        clearTimeout(typeInterval);
    }

    const fullText = element.dataset.fullText || '';
    let i = element.textContent.length; // 從當前已顯示嘅位置開始
    const speed = 30; // 每個字元顯示嘅速度（毫秒）

    function type() {
        if (i < fullText.length) {
            element.textContent += fullText.charAt(i);
            i++;
            // 滾動到最新內容，令用戶睇到打字效果
            element.scrollIntoView({ behavior: 'smooth', block: 'end' });
            typeInterval = setTimeout(type, speed);
        } else {
            // 所有內容都顯示完畢，清除計時器
            clearTimeout(typeInterval);
            typeInterval = null; // 重置
        }
    }
    type();
}
```
在「第二步：前端接收並處理流式數據」那段代碼的 `if (json.content)` 裡面，直接調用 `typeWriterEffect(currentAiResponseSpan);` 就能啟動打字機效果了。

## 我的實測心得與優化建議

我親測 DeepSeek API 的流式傳輸，響應速度真心不錯！大部分情況下，第一個字幾乎是秒回。但要讓打字機效果絲滑流暢，下面幾點得注意：

1.  **後端數據處理**：後端要麻溜地解析 DeepSeek 的 SSE 數據，然後光速轉發有效內容。慢一秒都會影響前端體驗哦。
2.  **前端緩衝區管理**：前端處理流數據時，數據包可能不完整，所以得搞好一個緩衝區（`buffer`），直到收到完整的 SSE 事件（以 `\n\n` 結尾）才去解析。
3.  **打字速度調整**：`speed` 參數可以自己調。太快就沒打字機那味兒了，太慢又讓人等得不耐煩。建議給用戶一個自定義選項。
4.  **錯誤處理**：網絡斷了、API 出錯怎麼辦？如果 DeepSeek API 掛了，後端要馬上通知前端，前端也要顯示友好的錯誤提示。可以看看這篇 [DeepSeek API 重試策略指南](/posts/deepseek-api-retry-guide/)，讓你的錯誤處理更完善。
5.  **自動滾動**：AI 回覆內容長的時候，聊天窗口要自動滾到最新內容，別讓用戶自己去翻。我的 `typeWriterEffect` 函數裡已經加了個簡單的 `scrollIntoView`。

## 常見問題 (FAQ)

**Q1：我 DeepSeek API 流式輸出為啥沒反應？**
**A1**：檢查這幾點：
*   後端調用 DeepSeek API 時，`stream: true` 有沒有設對？
*   後端響應頭 `Content-Type` 是不是 `text/event-stream`？
*   前端跨域（CORS）問題搞定了沒？後端得設好 `Access-Control-Allow-Origin`。

**Q2：打字機速度太慢/太快，怎麼調？**
**A2**：`typeWriterEffect` 函數裡的 `speed` 變量，它控制每個字顯示的間隔（毫秒）。數字越小，速度越快；數字越大，速度越慢。隨心所欲地調吧！

**Q3：DeepSeek 返回的是 Markdown 格式，前端怎麼顯示？**
**A3**：流式輸出通常給的是純文本。如果模型吐出來的是 Markdown，你得在前端收到完整或夠多的片段後，用 `marked.js` 或 `markdown-it` 這種 Markdown 解析庫轉成 HTML 再顯示。一般是等完整響應收齊後處理，或者每次更新都重新渲染已收到的 Markdown 部分。

**Q4：網絡斷了，打字機效果會怎樣？**
**A4**：網絡斷開或後端服務器出錯，前端 `fetch` 請求會報錯。這時候需要在 `catch` 裡處理這些錯誤，比如給用戶彈個「網絡異常」的提示。正式上線的應用，最好加上自動重連機制。

**Q5：能直接從前端調用 DeepSeek API 嗎？不走後端？**
**A5**：**強烈不建議！** 直接從前端調用會暴露你的 API Key，分分鐘被壞人盜用，讓你白白燒錢。乖乖走安全的後端服務中轉吧。可以去 [DeepSeek 網站](https://platform.deepseek.com/) 看看更多 API 安全建議。
